# XLSX template compatibility - Feature 012 M2

1. M2 supports ordinary XLSX workbooks through the existing MergeEngine, TemplateAnalyzer, CLI commands and HTTP document routes. Use AddMonoReport for dual-format composition. Existing Word constructors and DOCX/DOTX/DOCM/DOTM behavior remain supported. Excel templates/macros/binary packages (XLTX/XLSM/XLTM/XLSB) are outside scope.
2. Every worksheet needs one finite rectangular PrintArea. Worksheet-local and unambiguous workbook-scoped definitions are supported. Content outside PrintArea is disposable: output physically removes external rows, columns and cells, removes unused shared strings and expresses the retained report relative to A1. Required values must be inside PrintArea.
3. Scalar cell expressions reuse MonoReport paths, escapes, missing-value policy and built-in formatters. XLSX input data must be a JSON object. A complete unformatted scalar retains number, Boolean or string type; interpolation and explicit formatting produce text. Inserted strings are inert, including strings starting with an equals sign or containing braces. Literal SpreadsheetML escape-looking text and carriage returns retain their supplied values. Objects/arrays, malformed Unicode surrogates and XML control characters in JSON data produce safe field diagnostics.
4. Native numeric binding requires at most 15 significant decimal digits and a safe finite Excel-range round trip. Insignificant trailing zeroes and exponent notation are normalized for checking. Unsafe numbers fail with a recommendation to supply a JSON string or use explicit textual formatting. Existing Excel number formats, numeric date serials and the 1900/1904 workbook flag are preserved; ISO strings stay text. The engine does not infer dates or translate .NET patterns into Excel number formats.
5. Tested fidelity includes style references, row heights, column widths, authored hidden/zero-size states, wholly retained merges and nonanchor styling. Single-cell merges collapse; external merges disappear; partial and overlapping merges reject. Unchanged shared/inline rich strings and phonetic annotations are preserved. Rich-text field substitution rejects until the later fidelity milestone.
6. Page margins, orientation, scaling and safe non-coordinate print settings are retained. Tested selections/top-left cells, finite selection ranges and explicit page-break coordinates transform through the same crop geometry. A pane affected by removal of top/left margins rejects with a remedy. A worksheet synchronization anchor (`sheetPr/@syncRef`) also rejects if crop/expansion would move or discard it; an unchanged retained anchor is preserved. Print titles, user-defined names, tables, drawings/charts, conditional formatting, validation, hyperlinks, comments and unproven relationship/extension metadata currently reject rather than risk stale references. Expanded panes/manual page breaks reject until bounded M4 handlers are available. No general metadata repair is provided.
7. M2 supports one-level vertical regions (including consecutive equivalent multirow markers), independent runs separated by an unmarked row, and recursive horizontal blocks with parent-only columns. Controls use the approved long/short level/header forms in one left column and distinct top geometry rows. Parent headings render once per parent; existing owned merges follow fully contained children, collapse to ordinary cells for one survivor and disappear with empty owners. Partial/cross-owner projections and meaningful nonanchor content reject. Zero-width columns and zero-height separators retain their authored states.
8. Input order is authoritative. Contiguous logical groups require integer consistent $level and, for intersections, string $path; closed paths cannot reappear. Complete Cartesian records follow distinct horizontal collections in level/input order, with one descriptor when the product is empty. Tables outside the horizontal strip use ordinary records. Ordinary/parent-only fields use the first record, leaf fields use the corresponding tuple, and header fields/parents use their own axis. Positional permutations cannot be detected without IDs. Nested vertical hierarchy, group headers/footers and the full analyzer-scopes fixture remain M3.
9. Local scalar formulas over finite A1 cells/rectangles preserve relative/absolute/mixed flags, ordinary functions and authored nonreference text. Leaf operands select corresponding instances; static totals above/below/separators use faithful global ranges. Scalar operands must remain unique; empty, discarded, disjoint or ambiguous images reject with a source-cell remedy. Removed leaf formulas disappear. INDIRECT/OFFSET, structured/external/3-D/whole-axis, array/data-table/spill/implicit-intersection and unresolved names reject. Sheet-qualified/name/shared-formula binding remains M3. Formula caches/chains are removed and full recalculation requested; MonoReport does not evaluate formulas.
10. Core returns the existing warning collection, with optional stable XLSX codes. CLI retains its existing switches, binary output and failure-before-write behavior. HTTP keeps the existing routes and analysis schema; XLSX binary success uses the spreadsheet MIME type and document.xlsx, while Word keeps its existing MIME and document.docx. The existing warning-count header remains available. Complete successful CLI warning output and opt-in multipart warning transport are planned for M5.
11. Automated package/schema, semantic value, geometry, formula and transport checks establish the M2 structural slice. Manual Microsoft Excel opening, visual/print fidelity, recalculation and repair-prompt acceptance remain pending for final Feature acceptance. No XLSX Playground UI, Office runtime, formula evaluator, browser automation or application-specific resource ceiling is introduced by M2.
