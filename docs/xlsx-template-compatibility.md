# XLSX template compatibility

1. MonoReport supports ordinary XLSX workbooks through the existing MergeEngine, TemplateAnalyzer, CLI commands and HTTP document routes. Use AddMonoReport for dual-format composition. Existing Word constructors and DOCX/DOTX/DOCM/DOTM behavior remain supported. Excel templates/macros/binary packages (XLTX/XLSM/XLTM/XLSB) are outside scope.
2. Every worksheet needs one finite rectangular PrintArea. Worksheet-local and unambiguous workbook-scoped definitions are supported. Content outside PrintArea is disposable: output physically removes external rows, columns and cells, removes unused shared strings and expresses the retained report relative to A1. Required values must be inside PrintArea.
3. Scalar cell expressions reuse MonoReport paths, escapes, missing-value policy and built-in formatters. XLSX input data must be a JSON object. A complete unformatted scalar retains number, Boolean or string type; interpolation and explicit formatting produce text. Inserted strings are inert, including strings starting with an equals sign or containing braces. Literal SpreadsheetML escape-looking text and carriage returns retain their supplied values. Objects/arrays, malformed Unicode surrogates and XML control characters in JSON data produce safe field diagnostics.
4. Native numeric binding requires at most 15 significant decimal digits and a safe finite Excel-range round trip. Insignificant trailing zeroes and exponent notation are normalized for checking. Unsafe numbers fail with a recommendation to supply a JSON string or use explicit textual formatting. Existing Excel number formats, numeric date serials and the 1900/1904 workbook flag are preserved; ISO strings stay text. The engine does not infer dates or translate .NET patterns into Excel number formats.
5. Tested fidelity includes style references, row heights, column widths, authored hidden/zero-size states, wholly retained merges and nonanchor styling. Single-cell merges collapse; external merges disappear; partial and overlapping merges reject. Unchanged shared/inline rich strings and phonetic annotations are preserved. Rich-text field substitution is unsupported; use plain cell strings for fields.
6. Page margins, orientation, scaling and safe non-coordinate print settings are retained. Tested selections/top-left cells, finite selection ranges and explicit page-break coordinates transform through the same crop geometry. A pane affected by removal of top/left margins rejects with a remedy. A worksheet synchronization anchor (`sheetPr/@syncRef`) also rejects if crop/expansion would move or discard it; an unchanged retained anchor is preserved. Print titles, tables, drawings/charts, conditional formatting, validation, hyperlinks, comments and unproven relationship/extension metadata currently reject rather than risk stale references. Panes/manual page breaks in repeated reports reject; remove them before generation. No general metadata repair is provided.
7. Generation supports nested vertical group headers/footers and consecutive equivalent multirow markers, independent runs separated by an unmarked row, multiple worksheets, and horizontal blocks with parent-only columns. On each worksheet containing nested vertical regions, horizontal expansion is temporarily limited to a chain of at most two authored blocks, one per level, with one physical horizontal header row per level. No horizontal expansion is also supported. Deeper horizontal trees, multiple child blocks and multirow horizontal headers on such worksheets reject before data binding, even for empty/null collections. Simplify the controls or move the layout to a worksheet without nested vertical regions; existing flat worksheet behavior is unchanged. These limits do not cap data item counts or vertical nesting depth. Controls use the approved long/short level/header forms in one left column and distinct top geometry rows. Parent headings render once per parent; existing owned merges follow fully contained children, collapse to ordinary cells for one survivor and disappear with empty owners. Partial/cross-owner projections and meaningful nonanchor content reject. Zero-width columns and zero-height separators retain their authored states.
8. Input order is authoritative. Contiguous logical groups require integer consistent $level and, for intersections, string $path; closed paths cannot reappear. Complete Cartesian records follow distinct horizontal collections in level/input order, with one descriptor when the product is empty. Tables outside the horizontal strip use ordinary records. Ordinary/parent-only fields use the first record, leaf fields use the corresponding tuple, and header fields/parents use their own axis. Positional permutations cannot be detected without IDs. Vertical hierarchy comes from actual data levels and input order; the template selects presentation blocks by level. Unrendered data levels remain ancestors without omission warnings. Parent paths use actual data ancestors, and explicit $. accesses the document root. Unavailable vertical ancestors render empty with a warning by default and fail in strict missing-value mode. Analysis accepts structurally valid nested vertical templates and projects root collections, data-relative ancestor fields, separate horizontal scopes and duplicate source occurrences through Core, CLI and HTTP. Analysis requires no JSON and does not validate runtime matrix cardinality, ancestor availability or data-dependent formula images; a valid analysis does not guarantee generation success or horizontal eligibility.
9. Scalar formulas over finite A1 cells/rectangles preserve relative/absolute/mixed flags, ordinary functions and authored nonreference text. Same-workbook worksheet qualifiers, including quoted names and escaped apostrophes, follow the referenced sheet's final expansion and crop. References to the formula's own sheet retain leaf/group ownership; references to a different sheet require a unique scalar or a faithful contiguous range across that sheet's applicable instances. Records on different worksheets are not implicitly matched by position or value. Static totals above/below/separators use faithful global ranges. Empty, discarded, disjoint or ambiguous images reject with a source-cell remedy; removed leaf formulas disappear. INDIRECT/OFFSET, structured/external/3-D/whole-axis and array/data-table/spill/implicit-intersection forms remain unsupported. Shared scalar formulas are supported when their normalized formulas use the supported reference forms and have safe retained images. Explicit followers are normalized directly from their authored master in source coordinates before repetition and cropping, preserving relative/absolute/mixed flags and range endpoint orientation. Verified cases include followers encountered before the master, cropped masters supplying retained followers, ordinary-formula overrides and holes within a shared membership rectangle, and relocation through supported repetition and cropping. Surviving members are emitted as ordinary per-cell scalar formulas; shared groups are not recreated in output. Malformed groups and unsafe normalized operands fail with a source-cell remedy. Nested group-header/footer ranges select their own descendants and never borrow from the next group; scalar operands still require one unique cell. Simple workbook and worksheet names are supported when their definitions are explicit same-workbook worksheet-qualified absolute A1 cells or rectangles. Worksheet-local names take precedence over workbook names; worksheet qualification selects the lookup scope. Name operands keep their authored text, and definitions follow final geometry with fixed global meaning across repetitions. Names retain their scope and ordinary hidden/comment metadata. Relative/mixed or unqualified definitions, formula-valued/recursive aliases, multi-area definitions and unsupported function/macro metadata reject; a cell definition must remain a unique cell and a rectangle must remain complete and contiguous, including for unused names. Formula caches/chains are removed and full recalculation requested; MonoReport does not evaluate formulas.
10. Core returns the existing warning collection, with optional stable XLSX codes. CLI retains its existing switches, binary output and failure-before-write behavior. HTTP keeps the existing routes and analysis schema; XLSX binary success uses the spreadsheet MIME type and document.xlsx, while Word keeps its existing MIME and document.docx. The existing warning-count header remains available. Successful CLI warning details and opt-in multipart warning transport are not yet available; Core warnings and the existing HTTP warning-count header remain available.
11. Package/schema, semantic value, geometry, formula and transport checks cover the supported generation boundary. Microsoft Excel opening, visual/print fidelity, checked formula results and save/reopen remain part of final compatibility acceptance. MonoReport requests automatic full recalculation and does not evaluate formulas. No XLSX Playground UI, Office runtime or application-specific resource ceiling is provided.
