# XLSX template compatibility - Feature 012 M1

1. M1 supports static ordinary XLSX workbooks through the existing MergeEngine, TemplateAnalyzer, CLI commands and HTTP document routes. Use AddMonoReport for dual-format composition. Existing Word constructors and DOCX/DOTX/DOCM/DOTM behavior remain supported. Excel templates/macros/binary packages (XLTX/XLSM/XLTM/XLSB) are outside scope.
2. Every worksheet needs one finite rectangular PrintArea. Worksheet-local and unambiguous workbook-scoped definitions are supported. Content outside PrintArea is disposable: output physically removes external rows, columns and cells, removes unused shared strings and expresses the retained report relative to A1. Required values must be inside PrintArea.
3. Scalar cell expressions reuse MonoReport paths, escapes, missing-value policy and built-in formatters. XLSX input data must be a JSON object. A complete unformatted scalar retains number, Boolean or string type; interpolation and explicit formatting produce text. Inserted strings are inert, including strings starting with an equals sign or containing braces. Literal SpreadsheetML escape-looking text and carriage returns retain their supplied values. Objects/arrays, malformed Unicode surrogates and XML control characters in JSON data produce safe field diagnostics.
4. Native numeric binding requires at most 15 significant decimal digits and a safe finite Excel-range round trip. Insignificant trailing zeroes and exponent notation are normalized for checking. Unsafe numbers fail with a recommendation to supply a JSON string or use explicit textual formatting. Existing Excel number formats, numeric date serials and the 1900/1904 workbook flag are preserved; ISO strings stay text. The engine does not infer dates or translate .NET patterns into Excel number formats.
5. Tested static fidelity includes style references, row heights, column widths, authored hidden/zero-size states, wholly retained merges and nonanchor styling. Single-cell merges collapse; external merges disappear; partial and overlapping merges reject. Unchanged shared/inline rich strings and phonetic annotations are preserved. Rich-text field substitution rejects until the later fidelity milestone.
6. Page margins, orientation, scaling and safe non-coordinate print settings are retained. Tested selections/top-left cells, finite selection ranges and explicit page-break coordinates transform through the same crop geometry. A pane affected by removal of top/left margins rejects with a remedy. A worksheet synchronization anchor (`sheetPr/@syncRef`) also rejects if crop would move or discard it; an unchanged retained anchor is preserved. Print titles, user-defined names, formulas, tables, drawings/charts, conditional formatting, validation, hyperlinks, comments and unproven relationship/extension metadata currently reject rather than risk stale references. No general metadata repair is provided.
7. Repetition controls are recognized for source-dependency preparation, but public analysis and generation explicitly reject repeated templates in M1. Nested grammar, both-axis expansion, formula transformation and complete public analyzer acceptance for those templates remain M2/M3 work. Formula cells wholly outside PrintArea are discarded; obsolete calculation chains are removed. Output requests recalculation without calculating results.
8. Core returns the existing warning collection, with optional stable XLSX codes. CLI retains its existing switches, binary output and failure-before-write behavior. HTTP keeps the existing routes and analysis schema; XLSX binary success uses the spreadsheet MIME type and document.xlsx, while Word keeps its existing MIME and document.docx. The existing warning-count header remains available. Complete successful CLI warning output and opt-in multipart warning transport are planned for M5.
9. Automated package/schema, value, geometry and transport checks establish the M1 static slice. Manual Microsoft Excel opening, visual/print fidelity, recalculation and repair-prompt acceptance remain pending for final Feature acceptance. No XLSX Playground UI, Office runtime, formula evaluator, browser automation or application-specific resource ceiling is introduced by M1.
