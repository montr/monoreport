# Excel-saved compatibility fixture

1. **Provenance:** on 2026-10-27 the Product Owner approved the Excel-saved employees workbook as the source of the fixed test-owned employees-excel-saved.template.xlsx fixture and identified **Microsoft Excel for Mac 16.114.1 (26102031)** as the saving application. The supplied workbook came from Samples/xlsx-employees.template.xlsx; tests never read or regenerate it from that location. The original source remains unchanged. Its SHA-256 at import is b158693fefd6c0e31d47eba98f3e137c8a44f06c3f9a77f686389553e17f3b7f. The package itself identifies Microsoft Macintosh Excel with AppVersion 16.0300; that field is not the installed release/build. Exact preceding edit operations and whether the save was unchanged were not supplied, so neither is asserted as manual acceptance evidence.
2. **Sanitization:** only the copied workbook's absPath url in xl/workbook.xml and lastModifiedBy in docProps/core.xml were replaced, with /test-owned/compatibility/ and MonoReport compatibility tests respectively. Every other ZIP entry payload is identical to the approved source. XML was not reconstructed or normalized, and Excel's namespaces, wrappers, revision pointer, views, shared strings, styles and worksheet contents were retained. The sanitized fixture SHA-256 is 45b95b41a43ec7f4ad9dd8102439c35009609c017274e45e25263846f983fb93. These hashes record provenance, not byte-identical output requirements.
3. **Relevant parts and source behavior:** xl/workbook.xml contains the recognized save-path AlternateContent, revisionPtr, one Employees worksheet and PrintArea Employees!$B$1:$E$4. xl/worksheets/sheet1.xml contains an out-of-crop E9 selection in page-break preview at zoom 125, row heights, column widths, margins and portrait A4 print settings. xl/sharedStrings.xml contains the three column headings, Department/Name/Position expressions and the level-10/level-40 Data repetition controls. Department cells C3:E3 are merged. xl/styles.xml contains the Calibri 10 fonts, bold/theme-colored headers, fills and medium/hair borders. The theme and style extension structures are retained as authored.
4. **Automated expectations:** XlsxExcelSavedWorkbookTests reads only this maintained fixture from the test output directory; its JSON and expected results are test-owned constants. Public Core Analyze → Generate must produce two department headings and three independently bound employee rows, preserve Unicode and inert leading-equals text, crop to A1:D7, expand department merges to B3:D3 and B6:D6, preserve the relevant cell styles/dimensions/print/view settings, normalize selection to A1 and remove the recognized path/revision metadata and shared-string table. Source memory and fixture bytes remain unchanged. Input/output SDK validation accompanies semantic assertions and recalculation-policy checks. The project copies this fixture directly; there is no Samples, examples-manifest, temporary research, Excel, external-service or network dependency at test runtime.
5. **SDK schema findings:** the genuine source has horizontalDpi="0" and verticalDpi="0" on pageSetup in /xl/worksheets/sheet1.xml. The installed Open XML SDK 3.5.1 validator targeting Microsoft365 reports exactly two Sem_AttributeValueDataTypeDetailed schema errors for these attributes, in both input and output. The test requires precisely those attributes, values, node type, part, error ID and matching descriptions, with no additional findings. These values were preserved rather than silently repaired or removed. This is not a clean schema-validation result or evidence that Excel reopens output without repair; that manual check remains Pending.
6. **Coverage limits:** this workbook has no formula cells, native numeric/Boolean placeholders, partial-character rich strings, phonetic annotations, calcFeatures extension or no-PrintArea identity sheets. Existing generated subsystem checks continue to cover those supported scenarios; this fixture is not modified to manufacture their presence. It establishes genuine-save Core compatibility for its actual contents, not every combined scenario or every Excel capability.
7. **Remaining manual acceptance:** employees unchanged-save and representative content/whole-cell/partial-character edit workflows followed by Analyze → Generate → actual Excel reopen remain Pending unless scenario-specific results are supplied. Output reopen without repair, visual formatting, native-value confirmation, recalculated dependent formulas, dedicated mixed-workbook crop/identity/settings/view checks, and decoded non-BMP phonetic offsets/calculated PHONETIC results are not established by offline tests. The supplied provenance does not mark these checks Passed. See Feature 014 Implementation Plan section 10 for execution evidence and Stage 1's remaining gaps.
