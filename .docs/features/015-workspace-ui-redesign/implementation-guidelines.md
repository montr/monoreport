# MonoReport UI — Ant Design Implementation Guidelines

## Principles

1. Use standard Ant Design components and existing MonoReport editor/viewer integrations by default. The HTML mockup is a layout and behavior reference, not implementation code or a pixel-perfect styling contract.
2. Use Ant Design theme tokens and component APIs before introducing custom CSS. Avoid custom controls, menus, dialogs, tabs, radio-like switches, and splitters.
3. Keep the existing Monaco editor and DOCX/XLSX viewers. Do not reimplement features already provided by them, including document zoom when available.
4. Use minimal CSS only where a required layout or behavior cannot be achieved with the existing library APIs. Document the reason briefly.
5. Preserve keyboard accessibility, focus, and responsive behavior using standard controls.

## Component mapping

1. Main toolbar and pane headers: `Flex` / `Space`, `Button`, and appropriate layout primitives. Keep the controls in one compact toolbar; do not create bespoke toolbar widgets.
2. Examples: `Dropdown` with grouped `Menu` items (DOCX / XLSX), without a sidebar for now.
3. Generate: compose a primary Ant Design `Button` with `Dropdown` inside `Space.Compact`. The primary action generates a document; its text-first menu contains `Analyze Template` and `Generate Dataset...`, without decorative icons or a reserved icon column.
4. Examples: retain the grouped native Dropdown and add `BulbOutlined` with the Tooltip `Explore examples to see how MonoReport works`; do not otherwise change its appearance.
5. Application overflow commands: `Dropdown` + native `Menu` item layout, including API and `Clear Local Data…`. Keep it text-first and show the implemented `Shift+/` (`⇧ /` on macOS) as native right-side `extra` content for `Keyboard shortcuts`; do not add decorative icon columns.
6. Dataset and Template headers show one active filename as non-interactive text beside the heading/tabs; use `Flex` with native `Typography.Text` ellipsis and keep the dirty indicator in that same truncation-safe group. In the document header, keep the filename immediately after the Template/Result tabs and place stale Result freshness at the far right before the overflow menu. Do not add file selectors. Their overflow menus use `Dropdown` + `Menu`; labels omit redundant context words. Example filenames use `colorTextTertiary`, Local filenames use `colorText`.
7. Template / Result: `Radio.Group` with button-style `Radio.Button` options, or the existing equivalent standard Ant Design radio control. Do not implement custom toggle buttons.
8. Main split panels and expandable diagnostics layout: standard Ant Design `Splitter` / `Splitter.Panel`, including a narrow divider via supported API where possible. Use controlled sizes and native resize/collapse callbacks to persist split sizes and collapsed states; expanding restores the last non-collapsed user size. Keep persisted preferences in Clear Local Data. Avoid an in-house drag implementation.
9. Diagnostics: compact `Tabs` for `Problems` and `Analysis`. Apply the subtle gray token background to the tab strip only. Remove unnecessary Tabs nav margin/padding so the active underline reaches the strip's bottom edge while preserving compact tab height. Keep toolbar and content backgrounds unchanged. Use 12px Ant Design typography throughout the panel. Align compact icon-only Clear/Copy `Button`s with a small gap below the tabs and Tooltips titled `Clear` and `Copy`; show accessible semantic Error/Warning icons beside diagnostic codes without ordinal/action/severity prefixes. Do not render an empty Analysis toolbar or Output history.
10. Analysis: use a compact `Flex` row for validity and error/warning counts; keep summary, Requirements tree/types, and all section headings at readable 12px. Use Ant Design theme tokens to distinguish requirement names and types, reduce Tree node gaps with semantic styling, and preserve native indentation/behavior. Keep all diagnostic fields, prevent the Errors `Data path` header from wrapping, and top-align table body cells through Table semantic styles. Size Occurrences `Kind`, `Expression`, and `Path` for their content, retain the current widths, let `Location` use remaining width, and keep long values accessible. Omit the redundant Occurrences Part column.
11. Generate Dataset settings: `Modal` with `Form`, `InputNumber` for items per collection, and `Radio.Group` for `Random values` / `Empty values`. Do not include a destination selector. Create a new Dataset by default to avoid overwriting active data.
12. Confirmations: use `Modal.confirm` for potentially destructive operations and `Popconfirm` only for simple contextual confirmations. Preserve unsaved-change protection and clarify that clearing local application data does not delete files on disk.
13. Empty states: standard `Empty` and `Upload.Dragger` where appropriate; upload and close actions should be available without requiring an extra closing step before replacement.
14. Status and feedback: `Typography`, `Tag` / `Badge`, and `message` / `notification` where appropriate. Status and footer metadata use 12px typography; status shows `Ready`, `Success`, `Error`, `Cancelled`, `Generating...`, or `Analyzing...`, with semantic success/error/cancelled icons and colors aligned to labels and a small left inset. Align status icons and labels through native Flex layout. Clicking status opens Problems. Show completed operation duration in muted 12px text without clock time. Keep `MonoReport` and `dev` in the same muted color. Keep the loading animation on Generate during document generation and in status during active operations. Keep the active stale Result `Outdated` Tag with warning color, outlined variant, icon, and Tooltip at the right before the menu.
15. Icons: `@ant-design/icons`; do not embed custom icon assets for standard actions.
16. Shortcuts: reuse Monaco commands where available. Handle Dataset Save (`Cmd+S` / `Ctrl+S`) and Save As (`Cmd+Shift+S` / `Ctrl+Shift+S`) throughout the workspace, preventing the browser Save Page action while leaving dialogs and ordinary non-Monaco editable controls alone. `Cmd+Enter` / `Ctrl+Enter` generates a document and takes precedence over Monaco's conflicting Insert Line After binding. Do not invoke it in dialogs, during composition, or with Shift/Alt held. Display only actual platform shortcuts in menus and tooltips. List Generate document with this shortcut in the Keyboard shortcuts Modal's Workspace section and show the same platform keycaps in the primary Generate Tooltip, not on the dropdown arrow. Use an Ant Design text-on-spotlight token for those keycaps so they remain legible on the Tooltip surface; keep the Tooltip compact.
17. The Keyboard shortcuts Modal uses native `Flex` layout for section headings and command/keycap rows. Keep only the `Workspace` and `Dataset editor` sections, omit descriptions and table chrome, and preserve accessible shortcut names and native Modal focus/Escape behavior.

## Behavior boundaries

1. Keep the last successfully generated document visible when JSON changes or a later generation fails; indicate that the result is outdated.
2. Keep operation results in the Problems/errors and bottom status presentation. Do not add an operation-history tab or running timers.
3. File operations should use supported browser APIs with a clear fallback; an HTML mockup does not implement disk access.
4. One active Dataset, one active Template and a separately retained Result are visible workspace concepts; do not expose recent-file selectors. No Projects, new persistent file history, Office Add-in, or Data Sources implementation in this UI feature.
5. Review and safely remove demonstrably unnecessary CSS before layout changes. Remove CSS made obsolete by a component only when that component is replaced; preserve still-used styles until then.
