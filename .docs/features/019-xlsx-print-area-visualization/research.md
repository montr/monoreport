# Feature 019: Print Area research and alternatives

1. **Status and authority.** This document preserves the earlier Plan A investigation and records Plan B research requested on 2026-11-10. The Product Owner authorized this archive and investigation. Plan B implementation and a change to the selected product approach have not been approved. No existing Feature 019 documents were found when archiving began; this is the canonical research record rather than a second specification or implementation plan.

2. **Product boundary.** [The XLSX compatibility contract](../../../docs/xlsx-template-compatibility.md) supports one finite rectangular PrintArea per worksheet, requires it for repetition, and crops retained content to A1. Disjoint, duplicate, ambiguous and dynamic definitions are outside generation support. Ordinary defined names have a separate supported subset: worksheet-qualified absolute cells/ranges. Preview conveniences must not expand those engine guarantees. Generation rewrites PrintArea coordinates, so both approaches must read the Result workbook independently of the Template.

3. **Existing preview architecture.** [XlsxPreview](../../../web/src/components/XlsxPreview.tsx) consumes a Blob/File, dynamically imports the XLSX entry, and uses viewer-owned loading in worker mode. Hidden sheets are skipped, hyperlinks and drag resizing are disabled, and fonts are not downloaded. The read-only formula bar follows selection-context callbacks. [DocumentPanel](../../../web/src/components/DocumentPanel.tsx) supplies either the Template or Result source. The installed and locked package is `@silurus/ooxml` 0.89.8; the initial implementation adds an opt-in external-source build, not a replacement published dependency.

4. **PrintArea representation.** In XLSX, `xl/workbook.xml/definedNames/definedName` with name `_xlnm.Print_Area` contains the worksheet-qualified reference. `localSheetId` is the zero-based workbook sheet position, including hidden sheets, and is distinct from `sheetId`. Single cells and quoted sheet names with doubled apostrophes are relevant. Unions and formula-valued definitions cannot safely be reduced to a bounding rectangle. The stock parser exposes raw name/formula pairs through `Worksheet.definedNames`; it projects globals first and current-sheet locals last, but discards explicit scope attributes. See upstream `packages/xlsx/parser/src/lib.rs`, `parse_defined_names_for_sheet`, at the [pinned base](https://github.com/yukiyokotani/office-open-xml-viewer/tree/ed52f8747e6b0b25f7ebbdb3cb942b7a95f8f41b).

5. **Historical Plan A findings.** The canvas viewer does not expose per-cell DOM for CSS decoration. Native selection already projects ranges into frozen-pane fragments, suppresses clipped edges, mirrors RTL coordinates and refreshes after worker frames. Public `getCellViewportRect` supplies individual unclipped rectangles; there is no public pane-fragment projector, worksheet-body clipping geometry or universal displayed-frame event. Selection/find APIs cannot provide persistent exterior shading independently of selection. A native viewer-owned decoration was consequently preferable to an application overlay or custom renderer. The archived implementation shares the existing projector, adds an independent layer and retains scope metadata. Implementation evidence is maintained in [the handoff](implementation-handoff.md), with unresolved review findings in [the review record](implementation-review.md).

6. **Plan B objective.** An Excel-like Name Box dropdown would list navigable named ranges, including a user-facing `Print_Area` label for `_xlnm.Print_Area`, and activate, scroll to and select the chosen range. It offers discovery and navigation. It does not provide persistent processing-boundary shading: the highlight changes when the user selects another cell, and choosing a name intentionally changes the active cell and formula-bar content through existing viewer behavior.

7. **Published public APIs available for Plan B.** The exact 0.89.8 declarations are in `web/node_modules/@silurus/ooxml/dist/types/xlsx.d.ts`; this installed path is evidence, not a future archive dependency. The corresponding maintained sources are `packages/xlsx/src/workbook.ts`, `viewer.ts`, `types.ts` and `selection.ts` at the pinned base.

| Need | Published API | Implication |
|---|---|---|
| Load once and retain metadata access | `XlsxWorkbook.load(bytes, options)` | The application can own the workbook rather than parse it twice. |
| Discover effective names | `workbook.getWorksheet(index)` and `worksheet.definedNames` | Returns raw name/formula pairs, not resolved ranges or explicit scope. |
| Mount the same workbook | `XlsxViewer.fromWorkbook(container, workbook, options)` | The viewer borrows it; the caller must release the workbook after viewer teardown. |
| Track worksheets | `sheetIndex`, `sheetNames`, `onReady`, `onSheetChange` | Absolute indices must remain intact when hidden tabs are skipped. `onReady` is not a guarantee that worksheet content is ready. |
| Activate another worksheet | `await viewer.goToSheet(index)` | Needed before selecting a cross-sheet target. Explicit calls can activate hidden sheets despite skip mode. |
| Navigate | `await viewer.scrollToCell(firstCell, { align: 'nearest' })` | Navigates to one cell, does not select the range or fit the whole range. |
| Select | `viewer.setSelection(localA1Range)` or canonical selection state | Uses native selection, clipping and frozen-pane behavior. A defined name or sheet-qualified formula cannot simply be passed as the range string. |
| Observe resulting context | `onSelectionContextChange`, `selectionState` | Existing formula-bar behavior remains authoritative. |

8. **Clean Plan B architecture.** Replace viewer-owned loading with one application-owned `XlsxWorkbook` and a borrowed viewer. Supply parsing options, resource limits and worker timeout to workbook loading; supply display and interaction options to the viewer. Destroy the viewer before the owned workbook, including error, obsolete-load and unmount paths. Fetch the active worksheet's metadata asynchronously without delaying the first preview solely for the dropdown. Use an Ant Design Select in the existing formula-bar composition. A focused hook can coordinate current-sheet catalog and navigation state; a service can resolve supported references from injected workbook metadata. No application geometry, custom canvas paint, ZIP parser, additional dependency, upstream patch or local-library runner is needed for the initial supported subset.

9. **Selection sequence.** Resolve a choice to a target sheet index, first cell and sheet-local A1 rectangle. Activate a different worksheet only when necessary; await readiness, scroll to the first cell, then set the full range selection. Guard every asynchronous continuation by workbook/session generation and navigation request, and confirm the target worksheet before subsequent operations. Stale metadata or a superseded selection must not act on a replacement workbook. Do not enumerate every coordinate in the named range.

10. **Initial supported subset and discovery policy.** Prefer the active worksheet's effective names: this inventory already includes workbook-global names, including direct targets on another worksheet, plus current-sheet locals. Filter or disable non-range values, external/3-D references, relative ordinary names, aliases requiring evaluation, unions and dynamic definitions. Parse quoted sheet names and escaped apostrophes; retain original identifiers separately from display labels. For ordinary names, the parser's globals-before-locals ordering supports its existing last-match local-shadowing semantics. For `Print_Area`, reject conflicting or unresolved candidates instead of choosing an arbitrary duplicate. These are navigation policies, not a substitute for engine analysis.

11. **Published-package gaps.** There is no public workbook-wide named-range catalog, metadata-only worksheet fetch, scope identifier, hidden-name flag or general formula-to-range evaluator. Current-sheet `getWorksheet` can require full materialization, though it reuses the same workbook cache. Listing every other sheet's local names would require visiting those worksheets and can be expensive. Without raw scope, exact global/local labeling, malformed-scope detection and complete duplicate diagnostics cannot reproduce Excel's Name Manager. A bounded effective-name dropdown for valid, direct ranges remains feasible. Fully faithful scope inspection or dynamic-name support would need additional metadata/evaluation capabilities; they are optional extensions rather than initial Plan B requirements.

12. **Research probe.** [Published-package probe results](upstream/published-api-probe.json) preserve an in-memory, real three-sheet XLSX parse against a freshly installed, unpatched 0.89.8 package. It confirmed a hidden middle sheet does not renumber local scope, a quoted worksheet name survives, current-sheet local names follow globals, and dynamic formulas remain raw strings. The private Node parser adapter was used solely as research instrumentation. It is not proposed as an application API, and this probe does not verify browser navigation or close Plan A's patched-parser-to-renderer scope coverage gap.

13. **Comparison and effort.** These are engineering estimates, not measured delivery times; validation and final UX decisions affect them.

| Aspect | Plan A: native Print Area decoration | Plan B: Name Box navigation |
|---|---|---|
| UX | Ambient boundary and subtle exterior shading while selecting other cells | Search/discovery and an explicit jump to a named region |
| Selection/formula bar | Decoration preserves current selection | Choosing an item intentionally selects its range and updates active-cell context |
| Library dependency | Requires the archived native change or a future upstream release | Published 0.89.8 suffices for direct finite ranges |
| Frozen panes, scroll, zoom and RTL | Shared native projector and decoration lifecycle; browser appearance pending | Existing native selection and navigation handle geometry; no new overlay |
| Main complexity | Parser/model/API changes, shared rendering extraction, library build and review | Workbook ownership, supported-reference resolution, catalog state and asynchronous navigation |
| Initial estimate | Historical estimate: medium, approximately 3–5 engineer-days; unresolved review and browser work remain | Small-to-medium, approximately 2–3 engineer-days for the bounded catalog, integration and focused tests |
| Broader semantics | Formula evaluation and multiple Print Areas remain unsupported | Full scope-aware workbook catalog or dynamic names would increase scope; approximately 4–6 days or more and possibly an API addition |
| Maintenance | Upstream release/rebase coordination; local override is experimental | Application-level state/resolution policy on stable public APIs |

14. **Recommendation.** Preserve Plan A as a complete experimental/upstream candidate and resolve its review and browser acceptance issues before production adoption. Prefer Plan B as the next implementation candidate if near-term discovery/navigation is the product priority, because it can use the published package. The two capabilities are complementary: keep both as options if users need both navigation and persistent boundary visibility. Do not treat Name Box selection as an equivalent replacement for exterior shading, require a permanent fork, remove the current work, or implement Plan B without a new Product Owner decision.

15. **Decisions still needed.** Confirm effective active-sheet names versus a workbook-wide catalog; unsupported-name visibility; hidden-target navigation policy; whether a name choice should additionally fit/zoom the region; and whether both controls justify their UI space. The recommended initial scope is effective active-sheet names, direct finite ranges, disabled unsupported targets, the existing hidden-sheet policy and top-left navigation without an automatic zoom change.
