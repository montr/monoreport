# Feature 019: preserved review findings

1. **Evidence and status.** The Product Owner supplied the independent review finding categories for preservation. This record checks them against the archived patch; it is not a new independent-agent approval. No original code was fixed, no failing assertion was weakened, and no unresolved finding was omitted. Browser visual validation remains outside the authorized checks. Reproduction/build success establishes recoverability, not upstream readiness.

2. **R1 — overlapping-selection deduplication: confirmed structural change, unconfirmed visual regression.** Before extraction, one `seenFragments` set covered every selected area within `SelectionOverlay.update`. In the patch, each `projectRangeOverlay` call owns a fresh set. Distinct overlapping selections that clip to identical visible fragments can therefore append duplicates across calls. That difference is demonstrated by source inspection. A visible opacity/border regression has not been demonstrated: fills are still collected into a single non-zero SVG fill/mask operation, and the shared boundary path is not used for ordinary multi-area outlines. Existing passing selection tests do not specifically settle clipped-coincident fragments. Before upstream adoption, verify partially overlapping/contained selections, repeated clipped fragments, frozen-pane seams and active-cell cutouts against the previous renderer, or restore global deduplication in a separately approved fix. Do not describe this as a proven darkening defect.

3. **R2 — real-XLSX scope coverage: demonstrated coverage gap, not a demonstrated parser defect.** The added Rust test parses workbook XML, while the TypeScript decoration tests construct worksheet models and mock workbook loading. Historical real-WASM probes read the two single-sheet sample packages. A maintained real-XLSX fixture combining global/local shadowing, duplicate PrintAreas, an intermediate hidden worksheet, quoted sheet names and actual patched-parser-to-viewer propagation is missing. The new published-package research probe establishes stock-parser discovery behavior only; it does not close this Plan A integration gap. Add such a fixture and assertions in future approved implementation work.

4. **R3 — DefinedName compatibility: demonstrated API/data-shape change, broader breakage unconfirmed.** TypeScript adds optional `localSheetId?: string`, preserving ordinary structural use of existing name/formula pairs. Serialized local-name objects gain a property; consumers with strict schemas or exact-object expectations can require changes. In Rust, adding a public `Option<String>` field requires existing struct literals to supply it; the patch updates the internal legacy XLS constructor to compile. Thus Rust source-level compatibility implications are real, although no external consumer failure was reproduced. This model crate is an internal source-workspace component; the struct change is not itself proof of a breaking published JavaScript call signature. The raw-string representation intentionally preserves malformed XML scope and must not be advertised as a numeric resolved sheet ID. Retained-memory accounting was updated and focused compilation passed, but a wider consumer/API compatibility review remains necessary. The original parser comment saying the model carries no scope also becomes stale; it remains unchanged in the preserved patch.

5. **R4 — misplaced API documentation: demonstrated documentation defect.** In patched `packages/xlsx/src/viewer.ts`, the existing JSDoc describing runtime selection-color changes remains immediately above the newly inserted `setShowPrintArea` JSDoc/method. `setSelectionColor` consequently loses its properly positioned comment, and the adjacent documentation is misleading. This finding does not demonstrate a runtime selection failure. Move the existing comment back to its owner during a later approved code correction; the archived patch intentionally preserves the defect.

6. **R5 — browser visual validation: pending evidence.** Unit tests sample the emitted shading against native hit-testing under scroll, zoom, resize, frozen panes, RTL and delayed worker frames. They use a recording fake DOM, not browser painting. Actual SVG fill/stroke clipping, stacking under input/selection layers, responsive layout, browser timing and visual comparison with the previous renderer remain unverified. No browser automation or visual pass is claimed.

7. **Disposition.** R1 remains an unconfirmed regression risk; R2 is a confirmed test-coverage gap; R3 contains confirmed compatibility changes with unconfirmed downstream failures; R4 and the stale parser comment are confirmed documentation defects; R5 is an explicit validation gap. None is silently closed by the fresh archive reproduction. The Plan A artifact is suitable for continued review and implementation work, not a declaration of production acceptance.
