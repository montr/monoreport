# Feature 019: preserved Plan A implementation

1. **Status.** Plan A was implemented locally before this archive was authorized. It is an experimental implementation, not an upstream release or browser-accepted production feature. This task preserves that state; it does not repair code or approve Plan B. No application or original library source was changed during archiving.

2. **Canonical archive.** [The upstream patch](upstream/print-area-0.89.8.patch) is a byte-identical copy of the existing patch. [The integration patch](upstream/monoreport-integration.patch) separately preserves all eight MonoReport files, including the previously untracked runner and hook. [The manifest](upstream/manifest.json) identifies both bases, patch hashes and every reconstructed target file's SHA-256. [Reproduction instructions](upstream/reproduction.md) and [the executable reproduction sequence](upstream/reproduce.sh) make the archive independent of temporary source paths, session memory and pre-existing dependency trees. No upstream repository copy, dependency tree, compiled JavaScript, WASM or generated build output is included in this archive.

3. **Pinned upstream.** Repository: `https://github.com/yukiyokotani/office-open-xml-viewer`; release/package version: `@silurus/ooxml` 0.89.8, tag `v0.89.8`; exact base: `ed52f8747e6b0b25f7ebbdb3cb942b7a95f8f41b`. The earlier npm provenance inspection identified this commit; the manifest also pins the downloaded source archive by SHA-256. The MonoReport integration base is `5b9cb57879643082cf1cb6f57618b69816258ba5`.

4. **Native library changes.** Public options gain default-off `showPrintArea`; workbook and canvas-mounted viewers gain runtime `setShowPrintArea(boolean)`. A dedicated non-interactive SVG layer outlines the finite area and shades its exterior. Selection's frozen-pane projection and boundary-path construction move into a shared internal helper used by both painters. The decoration refreshes through existing native selection-overlay update points, including committed worker frames, scrolling, zoom, container resizing and worksheet activation; it is stacked below selection and interaction layers. The application does not calculate geometry or change workbook content.

5. **Parser/model changes.** Defined names retain authored `localSheetId` as optional raw text so malformed local scope cannot masquerade as a global definition. Rust retained-memory accounting includes that string. The legacy XLS name constructor supplies `None` solely to remain compatible with the changed Rust struct. Reference handling permits one finite worksheet-qualified rectangle or cell, including escaped quoted names. Conflicts, multi-ranges, aliases and formula-valued/dynamic areas yield no decoration. An unresolved global PrintArea conservatively suppresses decoration because its target worksheet cannot safely be inferred.

6. **Library patch inventory.** The 13 files cover `packages/xlsx/src/viewer.ts`, `types.ts`, the public API baseline, `internal/sheet-surface.ts` and its test, `internal/viewer/selection-overlay.ts`, new `range-overlay.ts`, new `print-area-overlay.ts`, new `print-area.test.ts`, `model/src/lib.rs`, `model/src/retained.rs`, `parser/src/lib.rs`, and `packages/legacy-office/parser/src/xls/names.rs`. The manifest gives the precise paths and resulting hashes. New files are complete patch entries rather than referenced temporary files.

7. **MonoReport integration.** The eight archived paths are `web/package.json`, `webpack.config.cjs`, `vitest.config.ts`, `scripts/local-ooxml.mjs`, `src/components/XlsxPreview.tsx`, `src/components/XlsxPreview.test.tsx`, `src/hooks/useXlsxPrintArea.ts` and `src/styles.css`. The runner builds only XLSX using upstream's release configuration, preserving a self-contained worker, sidecar and declarations. It does not edit installed package contents or the dependency lockfile. Webpack/Vitest aliases select the external build; an ephemeral TypeScript configuration selects its declarations. The existing published package remains usable without that alias.

8. **UI and lifecycle.** Template and Result share an Ant Design Show Print Area checkbox. It starts off and is exposed only when the loaded viewer supports the new method. The display preference persists across viewer replacement while the component remains mounted, but every workbook supplies its own PrintArea metadata. The hook detaches the old viewer before destruction. Toggling calls the native setter without reloading or changing selection/formula-bar logic; downloads and engine generation are untouched.

9. **Historical verification, before archiving.** Reported passes were 171 library tests across 11 focused files, two parser scope tests, 181 frontend tests across 13 files, library TypeScript checking, viewer API symmetry, legacy XLS compilation, frontend checking against both the published and local declarations, the integrated production build, and whitespace checks. A real WASM probe of the two bundled examples exposed their areas and local scope zero. Those probes were single-sheet observations, not a retained multi-sheet end-to-end fixture. These historical results are distinct from the fresh reproduction evidence recorded in [verification results](upstream/verification-results.json).

10. **Limitations and readiness.** No browser automation, screenshots, browser visual acceptance or stress testing was performed. Fake-DOM mask/hit-test consistency checks do not prove Excel rendering fidelity, display stacking in actual browsers, or pagination. Dynamic formulas and multi-range PrintAreas are deliberately unresolved. The source patch is preserved with all review issues intact, including the misplaced API comment and potential clipped-overlap deduplication risk; see [the review record](implementation-review.md). Passing checks do not close those issues.

11. **Archive completeness.** During archiving, every changed original upstream source file was compared with the pristine commit archive, and new source files were checked against the patch inventory. Exactly 13 upstream paths were covered. Reconstructed source hashes are checked for all 13 upstream and eight MonoReport target files before builds. The original temporary source tree and original patch were not deleted or modified. The fresh reproduction workspace is disposable verification output and is not required by future work.
