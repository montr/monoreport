# Reproducing the preserved Plan A implementation

1. **Inputs and independence.** The canonical inputs are `manifest.json`, `print-area-0.89.8.patch`, `monoreport-integration.patch` and `reproduce.sh` in this directory, plus publicly obtainable upstream/tool sources and this MonoReport repository's recorded base commit. No existing temporary checkout, installed project dependency directory or Codex context is an input. This is a source-and-instructions archive, not an offline mirror of registries. Internet access and availability of the recorded Git objects/releases are required.

2. **Exact source identities.** Upstream is `https://github.com/yukiyokotani/office-open-xml-viewer`, commit `ed52f8747e6b0b25f7ebbdb3cb942b7a95f8f41b`, release `v0.89.8`, package `@silurus/ooxml` 0.89.8. The manifest records the upstream commit archive URL, its SHA-256, the MonoReport repository origin, both patch hashes and 21 reconstructed target-file hashes. MonoReport's integration patch is based on `5b9cb57879643082cf1cb6f57618b69816258ba5` in `git@github.com:montr/monoreport.git`. A future machine can obtain it with a normal authorized clone of that repository; a shallow clone missing the base object needs `git fetch origin 5b9cb57879643082cf1cb6f57618b69816258ba5` before reproduction. Those are future setup instructions, not Git operations performed on the current working tree. Do not apply either patch blindly to a different revision or assume its API is present in the published package.

3. **Toolchain and prerequisites.** The validated target is Apple Silicon macOS with Command Line Tools/C linker. Bootstrap also provides paths for Intel macOS and x86-64 Linux, but those platforms are not validated here. Required host utilities are Bash, Git, curl, tar, awk and Python 3. Node 26.13.0, npm 12.2.2, pnpm 11.13.0, Rust 1.99.1 with `wasm32-unknown-unknown`, and wasm-pack 0.15.1 are pinned by the manifest/bootstrap. The Rust lockfile selects wasm-bindgen 0.2.118. Rustup 1.28.2 bootstraps the compiler without editing shell profiles. Keep a functioning native linker/SDK for parser test and tool builds. pnpm 11.13.0 is registry-deprecated as broken; it was retained to match upstream and successfully used here, not silently upgraded.

4. **One-command fresh reproduction.** From any checkout of MonoReport containing this archive and the recorded base Git object, run `bash .docs/features/019-xlsx-print-area-visualization/upstream/reproduce.sh "$PWD/web/.vite/feature019-reproduction-fresh"`. The workspace path must not already exist. It is ignored verification output rather than an archived repository copy. The script downloads a fresh Node distribution, explicitly installs npm 12.2.2, installs isolated Rust/wasm-pack/pnpm tools, creates fresh package caches/stores, and installs both dependency trees. Node's downloaded SHASUMS file and the archived source/patch hashes are checked. `TMPDIR`, `CARGO_HOME`, `RUSTUP_HOME` and `WASM_PACK_CACHE` point inside the new workspace. No original source or current dependency directory is reused.

5. **Obtain and apply upstream sources manually.** Let `ARCHIVE` be this directory's absolute path and `WORK` an empty workspace. Download `https://codeload.github.com/yukiyokotani/office-open-xml-viewer/tar.gz/ed52f8747e6b0b25f7ebbdb3cb942b7a95f8f41b` and check the manifest's source SHA-256. Extract it into `"$WORK/upstream"` with `tar -xzf "$WORK/downloads/upstream.tar.gz" --strip-components=1 -C "$WORK/upstream"`. Run `GIT_CEILING_DIRECTORIES="$WORK" git -C "$WORK/upstream" apply --check --whitespace=error-all "$ARCHIVE/print-area-0.89.8.patch"`, then `GIT_CEILING_DIRECTORIES="$WORK" git -C "$WORK/upstream" apply "$ARCHIVE/print-area-0.89.8.patch"`. The ceiling prevents discovery of a containing repository when using archive-extracted source. This pristine exact-commit source tree is the fresh checkout equivalent; no branch, index or history is created or changed.

6. **Restore the separately preserved integration.** Extract MonoReport with `git archive 5b9cb57879643082cf1cb6f57618b69816258ba5 | tar -x -C "$WORK/monoreport"` from this repository. Check and apply `"$ARCHIVE/monoreport-integration.patch"` in that fresh tree with the same Git ceiling policy. The integration patch contains six modified tracked files plus the complete new runner and hook. The script verifies all 13 upstream and eight MonoReport target-file hashes against the manifest before installing/building. The application source in the original working tree is not an input to this restore.

7. **Install from locked dependency definitions.** With the pinned Node/pnpm tools on PATH, run `node "$WORK/tools/pnpm/node_modules/pnpm/bin/pnpm.cjs" install --frozen-lockfile --ignore-scripts --filter @silurus/ooxml --filter @silurus/ooxml-xlsx... --store-dir "$WORK/tools/pnpm-store"` in the fresh upstream root. In the restored MonoReport `web` directory, run `npm ci --no-audit --no-fund --registry https://registry.npmjs.org`. Use the script's workspace-local npm cache. Do not copy installed dependencies from the original workspace or patch anything in `node_modules`.

8. **Build and connect the library.** In the restored MonoReport `web` directory run `npm run ooxml:local -- "$WORK/upstream" build-library`. The archived runner executes the locked XLSX WASM build, upstream's generated `reinit` helper, core declarations, the release Vite configuration limited to XLSX, the XLSX source-worker sidecar and XLSX declarations. It keeps release worker bundling self-contained; simply substituting the private per-package Vite build is not the recorded integration. To open a development server later, run `npm run ooxml:local -- "$WORK/upstream" dev`. To produce the integrated production bundle, run `npm run ooxml:local -- "$WORK/upstream" build`. The runner sets `MONOREPORT_OOXML_XLSX` for exact-entry aliases and a generated declaration override for typechecking. Normal commands without this override use the published package; the checkbox is hidden when that package lacks the new setter. Starting a server or browser is not part of this reproduction script.

9. **Verification commands.** In upstream run `cargo test --locked -p xlsx-parser defined_name_scope_tests -- --nocapture`, `cargo check --locked -p legacy-office-parser --features direct-xls`, `./node_modules/.bin/tsc -p packages/xlsx/tsconfig.json --noEmit --pretty false`, and `node scripts/check-viewer-api-symmetry.mjs`. The complete 11-file focused Vitest invocation is recorded exactly in `reproduce.sh`. In restored MonoReport `web`, run `npm run ooxml:local -- "$WORK/upstream" test --run`, the corresponding `typecheck` action, and the corresponding `build` action. Two parser tests, 171 library tests and 181 frontend tests were the historical expected counts. Counts are descriptive evidence, not assertions to preserve at the expense of test quality. No browser or stress suite is invoked.

10. **Results and scope of reproducibility.** The script preserves phase logs under the new workspace's `logs/` and exit codes in `results.tsv`. The canonical archived outcome is [verification-results.json](verification-results.json); the handoff distinguishes prior results from fresh reproduction. The final clean run on Apple Silicon passed all 18 phases, including two parser tests, 171 library tests, 181 frontend tests, both typechecks and the integrated production build. All 21 restored source-file hashes matched. An earlier bootstrap attempt used Node's bundled npm 11.20.0 and encountered an end-of-run harness error after the checks; the script was corrected and rerun unchanged with pinned npm 12.2.2. No implementation code was repaired. This verifies exact source reconstruction and functional build/test reproducibility. Byte-identical generated WASM/bundles are not claimed: native SDK/linker, tool packaging and build paths are not fully hermetic. Generated binaries and full checkouts must remain outside this archive.

11. **Review issues are retained.** [The review record](../implementation-review.md) preserves the overlap deduplication risk, real-XLSX scope integration coverage gap, DefinedName compatibility implications, misplaced API comment and pending browser validation. The archived patch is not amended to make review findings disappear. Applying/building it successfully does not resolve these issues.
