## 3. New findings

### 3.1. F4 — P1: merge collapse silently changes the logical owner of scalar and range references

1. **Locations:** [XlsxGeometryPlanner.Owners.cs:17](/Users/blackish/Projects/monoreport/MonoReport/Services/Xlsx/XlsxGeometryPlanner.Owners.cs:17) replaces the destination placement with the source anchor; [line 64](/Users/blackish/Projects/monoreport/MonoReport/Services/Xlsx/XlsxGeometryPlanner.Owners.cs:64) falls back to physical interval projection when the operand has no retained-content entry; [XlsxFormulaPlanner.cs:66](/Users/blackish/Projects/monoreport/MonoReport/Services/Xlsx/XlsxFormulaPlanner.cs:66) accepts that projection. No check establishes that a physical target still belongs to the referenced source cell.
2. **Independent public reproduction:** PrintArea B7:G12; parent D:E; child D; A7 `$h(1).Bids`; D7 `{Rate}`; E7 blank; merge D7:E7; A8 `$h(2).Criteria`; body A10 `$l(10).Items`, B10 `{Name}`, E10 formula `E7*2`. Supply two Bids with Rate 10/20, empty Criteria and descriptor records for the logical rows. E is the valid trailing parent-only column. The authored nonanchor E7 contains neither a value nor a formula.
3. **Actual:** Analyze is valid and Merge succeeds. D7's rates are correctly retained at C1=10 and D1=20, but the body formulas become `C1*2` and `D1*2`. Thus a source operand naming **blank E7** silently becomes an operand naming **D7's rate**. Independently probing `SUM(E7:E7)` emits `SUM(C1:C1)` / `SUM(D1:D1)`; `COUNTBLANK(E7:E7)` likewise targets those nonblank rate cells. The same behavior repeats for a second logical row. All successful packages have zero Open XML validation errors.
4. **Expected versus actual semantics:** preserving the source blank referent would give zero for the scalar multiplication and SUM, and one for COUNTBLANK. The emitted operands would instead give 20/40, 10/20 and zero respectively. These are consequences of the inspected operands and native values, **not claims of executed spreadsheet recalculation**. Since the surviving physical cell must hold the preserved anchor, reject a reference whose distinct blank owner cannot be faithfully represented with `template.xlsx_unsafe_formula`; do not reinterpret it as an anchor reference. Source D7 references must continue to follow the moved anchor correctly.
5. **Correction-induced regression confirmed:** ran the same public runner against a copied, preserved pre-correction Core assembly from the original review. Its E7 image was blank; current output contains 10/20 at the same formula referents. Raw XML assertions independently confirm this difference. Historical artifacts were not overwritten. Evidence: `numeric-collapse-E7-2-*`, `numeric-collapse-SUM-E7-E7--*`, `numeric-collapse-COUNTBLANK-E7-E7--*`, `probes.log`, `historical-comparison.log`, and `check-output.py` in the temporary evidence directory.
6. **Recommended correction:** represent displaced destination identities as well as retained anchors when finalizing ownership. Validate scalar and range operands against those identities before accepting physical images; reject aliasing or mixed images that cannot preserve semantics. Add public regressions for anchor versus nonanchor operands, numeric rates, scalar and bounded-range forms, repeated parents/rows and collapse versus nonempty children. This is required safety under spec sections 6.7/6.9 and plan sections 4.3/4.4, not M3 sheet/name/group support or a request for general merge repair.

### 3.2. F5 — P2: nonempty parent-owned body merges retain extra meaningful anchor copies in nonanchors

1. **Locations:** [XlsxGeometryPlanner.Owners.cs:17](/Users/blackish/Projects/monoreport/MonoReport/Services/Xlsx/XlsxGeometryPlanner.Owners.cs:17) replaces only the projected anchor coordinate, leaving other physical copies of that source anchor; [line 27](/Users/blackish/Projects/monoreport/MonoReport/Services/Xlsx/XlsxGeometryPlanner.Owners.cs:27) suppresses duplicates only on header rows. [XlsxTemplatePlanner.Instances.cs:44](/Users/blackish/Projects/monoreport/MonoReport/Services/Xlsx/XlsxTemplatePlanner.Instances.cs:44) consequently binds the remaining body copies as leaf intersections. The nonanchor-content check in [XlsxGeometryPlanner.Merges.cs:60](/Users/blackish/Projects/monoreport/MonoReport/Services/Xlsx/XlsxGeometryPlanner.Merges.cs:60) checks source nonanchors, not these generated copies.
2. **Independent public reproduction:** use PrintArea B7:G12, parent D:E, child D, two parents, three criteria and one-level Items. Put `{Name}` at D10, a blank styled E10, and author existing merge D10:E10. Supply six records per logical row: first name `descriptor0`, then distinct `tuple1` through `tuple5`; repeat with a second logical row. This is a parent-owned merge enclosing its entire child, with no meaningful authored nonanchor content.
3. **Actual:** Analyze and Merge succeed. The body merges are C4:F4, G4:J4, C5:F5 and G5:J5. The first row's retained anchors C4/G4 correctly contain `descriptor0`, but **D4=`tuple1`, E4=`tuple2`, H4=`tuple4`, I4=`tuple5` remain inside those merges as meaningful nonanchor cells**. The second row has the corresponding problem. F4/J4 retain the authored blank nonanchor border style, so a style-only assertion would miss the defect. Output is schema-valid.
4. **Expected:** emit the parent-owned ordinary field once per parent and logical row; nonanchor copies remain empty with their authored styling. Do not generate additional hidden intersection values underneath the authored merge. This violates the M2 ownership/content guarantees in spec sections 3.4.5–3.4.6 and plan section 4.3.7; it does not require nested vertical groups or new XLSX capabilities.
5. **Classification:** this is a newly demonstrated **pre-existing M2 defect**, not a regression attributed to the corrections. The isolated pre-correction assembly generates the same extra nonanchor values. The correction improves the retained Beta anchor's parent scope, but does not remove the extra leaf copies. Evidence: `body-merge-child-anchor-source.xlsx`, `body-merge-child-anchor-output.xlsx`, their separate historical-output counterparts and independent `check-output.py` assertions.
6. **Recommended correction:** finalize one content owner for every projected merge instance, including body rows, and suppress the redundant generated copies of its anchor while preserving their styles. Retain the meaningful authored-nonanchor rejection. Add a public body-merge regression using distinct tuple values and assertions for every nonanchor, both parents and multiple logical rows; do not broaden the merge envelope or silently discard independently authored content.
