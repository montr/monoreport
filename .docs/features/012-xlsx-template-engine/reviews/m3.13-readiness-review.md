## 1. Verdict

1. **Ready with clarifications.** The architecture and existing implementation support a small M3.13 change using the ordinary formula pipeline. No new shared-formula relocation engine, output-group mechanism or architecture decision is needed. The plan should make its pre-render invariants, generated-package acceptance and external F-001 dependency explicit before implementation.
2. This verdict assesses the implementation approach, not implementation authorization or acceptance of unrestricted shared output. F-001 remains an unresolved correctness defect in the geometry consumed by formulas. Independent implementation could technically be separated from its repair, but the Owner has now selected F-001 first. Neither this review nor acceptance of M3.12 waives that defect or the pending manual Excel evidence.

## 2. Responsibilities and exact output semantics

1. **Input inventory belongs to M3.11.** [XlsxFormulaReferences.Shared.cs:46](../../../../MonoReport/Services/Xlsx/XlsxFormulaReferences.Shared.cs#L46) reads worksheet-local shared groups before crop. A master is identified by its `ref`; followers may contain redundant text, which does not override the master. Explicit ordinary formulas and holes inside the membership rectangle remain independent; the rectangle does not synthesize members. Existing metadata validation rejects missing/conflicting masters, invalid indices or membership, overlapping master ranges and unsupported formula structures.
2. **Source expansion belongs to accepted M3.12.** [Shared.cs:21–37](../../../../MonoReport/Services/Xlsx/XlsxFormulaReferences.Shared.cs#L21) parses each needed master and copies explicit retained members directly from it in source coordinates, respecting dollar flags and reparsing changed spans. [XlsxTemplatePlanner.cs:33–36](../../../../MonoReport/Services/Xlsx/XlsxTemplatePlanner.cs#L33) invokes that work, and [lines 58–113](../../../../MonoReport/Services/Xlsx/XlsxTemplatePlanner.cs#L58) attach the normalized parsed formula while retaining source metadata for provenance. M3.13 must not expand the group again.
3. **Owner relocation belongs to the existing formula finalizer.** [XlsxFormulaPlanner.cs:48–83](../../../../MonoReport/Services/Xlsx/XlsxFormulaPlanner.cs#L48) already binds parsed source formulas per surviving placement and attaches prepared formula text to the final workbook plan. A normalized follower should enter this same path. Its own source cell and placement determine leaf/group/global ownership; the original master's placement or shared range must not select that ownership.
4. **Output is ordinary scalar formulas.** [Plan §4.4.8:126](../implementation-plan.md#L126) explicitly requires scalar output, consistent with [Spec §6.11:163](../feature-spec.md#L163) and [architecture §5.2.4:108](../architecture-assessment.md#L108). Every surviving master and follower emits one ordinary formula element containing its complete relocated text. There are no output masters or followers, empty follower formula elements, shared-group identifiers, or shared ranges. Emit no shared formula type, `si` or `ref`; do not allocate replacement identifiers, elect a replacement master, split groups or reconstruct rectangular output groups.
5. **Removed members need no output representation.** A cropped master can still supply the authored formula for retained followers because normalization precedes geometry. Its formula operands are checked through each retained member's normalized formula; the discarded master's own placement need not survive. A shared membership range crossing PrintArea or ownership boundaries is not itself an output referent and need not remain rectangular after generation. A removed formula placement emits nothing; surviving formulas must still have safe referents.
6. **Rendering already implements the required storage form.** [XlsxDocumentRenderer.cs:35–38](../../../../MonoReport/Services/Xlsx/XlsxDocumentRenderer.cs#L35) replaces source formula XML with prepared scalar text, removes stale cached/inline values and the cell's stale type attribute, and preserves the other authored cell properties. [Lines 63–68](../../../../MonoReport/Services/Xlsx/XlsxDocumentRenderer.cs#L63) remove the calculation chain and request automatic full recalculation. The renderer should consume finalized decisions without parsing formulas or inferring geometry.
7. **No competing mechanism was found.** Source copy and structural relocation are separate operations with separate purposes. Applying output-position deltas before relocation would double-transform references. Repeating group expansion in finalization or adding a shared-group writer would duplicate existing work and contradict the scalar-output plan.

## 3. Findings

1. **Major — M3.13 needs an explicit external F-001 acceptance dependency.** [The checkpoint:215](../implementation-plan.md#L215) names repeat/crop coverage without acknowledging the inherited source-completeness gap. [XlsxGeometryPlanner.Merges.cs:12–19](../../../../MonoReport/Services/Xlsx/XlsxGeometryPlanner.Merges.cs#L12) and [XlsxGeometryPlanner.Owners.cs:105–132](../../../../MonoReport/Services/Xlsx/XlsxGeometryPlanner.Owners.cs#L105) check the surviving output shape while `Complete` measures PrintArea containment. A distinct source portion can disappear through owner filtering while the remaining output is contiguous. The existing [OwnerRanges regression:11–41](../../../../MonoReport.Tests/Services/Feature012FormulaTests.OwnerRanges.cs#L11), [F-001 investigation](f-001-investigation.md) and [F-001 architecture analysis](f-001-architecture.md) document both ordinary and content-owner paths. [F-M312-1 assessment §7.7:82](f-m312-1-architecture.md#L82) explicitly warns against claiming M3.13 acceptance while this remains unresolved. **Smallest plan clarification:** record the separate dependency and retain the failing rejection expectations. Do not incorporate its repair, relax owner selection, or bless partial-source contraction inside M3.13. The Owner has selected separate F-001 work first.
2. **Major — Replacing the blanket guard needs a positive finalization invariant.** Both static validation and finalization invoke [RequireScalarFormulas:86–95](../../../../MonoReport/Services/Xlsx/XlsxFormulaPlanner.cs#L86), which currently rejects every retained shared member. Simply deleting it would leave no explicit check that every surviving formula receives prepared text: [Finalize:74](../../../../MonoReport/Services/Xlsx/XlsxFormulaPlanner.cs#L74) skips missing parsed entries, while [Render:29–40](../../../../MonoReport/Services/Xlsx/XlsxDocumentRenderer.cs#L29) starts from cloned source XML. This is a prospective invariant gap, not a demonstrated failure through the currently guarded public path. **Smallest clarification:** require normalized parsed formulas for retained shared members and finalized text for every surviving, nonsuppressed formula placement before rendering; fail explicitly on an inconsistent internal plan. Reuse the existing services and final plan rather than adding a new state framework.
3. **Major — The checkpoint's test row is insufficiently explicit about output acceptance.** [M3.13:215](../implementation-plan.md#L215) specifies boundaries and stale metadata but does not explicitly require successful generated-package structure and round-trip assertions. Existing [SharedInventory:176–190](../../../../MonoReport.Tests/Services/Feature012FormulaTests.SharedInventory.cs#L176) and [SharedCopy:95–118](../../../../MonoReport.Tests/Services/Feature012FormulaTests.SharedCopy.cs#L95) deliberately verify normalization and pending-output rejection. They do not establish successful shared-member relocation/output. **Smallest clarification:** add independently expected formulas, raw formula metadata/cache assertions, package reopening and a representative save/reopen check to the M3.13 acceptance row; reuse existing recalculation coverage for unchanged mechanics.
4. **Minor — Existing normalization probes must not become success fixtures indiscriminately.** The default [SharedInventory fixture:291](../../../../MonoReport.Tests/Services/Feature012FormulaTests.SharedInventory.cs#L291) references its own D4 master and E4, whereas [XlsxFixture:34](../../../../MonoReport.Tests/Services/XlsxFixture.cs#L34) retains B3:D5. The [crossing probe:178–180](../../../../MonoReport.Tests/Services/Feature012FormulaTests.SharedCopy.cs#L178) references disposable A3 and includes its own formula cell. These are useful source-level probes, but removing the pending-output guard does not make them successful noncircular output or calculation oracles. **Smallest clarification:** use a fully retained, noncircular package for success proofs; preserve applicable crop/ambiguity negatives. Repeated fixtures containing absolute references can also remain unsafe when those anchors acquire multiple output instances.

## 4. Relocation and validation requirements

1. Preserve the approved F-M312-1 path in [FormulaPlanner.cs:138–163](../../../../MonoReport/Services/Xlsx/XlsxFormulaPlanner.cs#L138): independently normalize source row/column bounds for geometry, project the entire rectangle, then restore each endpoint's orientation and original flags. Preserve range syntax at coincident endpoints and the approved first-low/last-high convention when an equal source axis expands. Do not sort lexical endpoints, swap dollar flags, or relocate only the two corners independently.
2. Keep [existing ownership selection:130–152](../../../../MonoReport/Services/Xlsx/XlsxFormulaPlanner.cs#L130): group-header/footer ranges use their own descendants; body/leaf formulas use current ownership; static totals remain global; dollar flags suppress copying rather than structural relocation. Cross-sheet paths remain worksheet-local and are cleared for another target sheet. Simple-name operands retain their text while definitions relocate independently. Mixed-owner comparison remains in force. Shared membership provides no exception to these rules.
3. Before rendering, require valid source metadata, successful normalization, resolved sheet/name identities, valid final placements and safe reference images on every worksheet. Scalars must identify a unique cell; ranges must have a faithful contiguous image. Reject cropped, empty, disjoint, ambiguous, displaced-source and incompatible mixed-owner images with source context and an actionable remedy. F-001 prevents claiming that current geometry proves complete source coverage; its separate correction must establish that guarantee rather than a shared-specific workaround.
4. Preserve the distinction between source validation and survival-dependent relocation. Malformed shared metadata or an unsafe required source copy is not hidden by a zero repetition count. After source normalization, a removed or suppressed formula placement needs no relocation; its absence does not permit a surviving formula to reference removed content. Preserve existing unsupported array/data-table/spill/constructed-reference boundaries.
5. Finalize every worksheet before rendering any worksheet, as already ordered by [XlsxTemplateHandler.cs:48–65](../../../../MonoReport/Services/Xlsx/XlsxTemplateHandler.cs#L48). Missing normalization or prepared output must not fall back to authored follower XML, stale caches, empty formulas or guessed values. Preserve deterministic bounded diagnostics, unchanged input and no returned workbook on failure.

## 6. Recommended implementation sequence and focused acceptance tests

1. **After separate F-001 work and explicit M3.13 authorization, establish a static success slice.** Use an actual shared XLSX package with a later master, redundant follower text, an ordinary override and a hole. Keep all referenced data inside PrintArea and formulas away from their own inputs. Assert independently authored literal output formulas after crop, not output computed by calling the production copy/relocation helpers as the oracle.
2. **Replace the blanket shared-output restriction and reuse finalization.** Prove retained shared members are normalized and every surviving formula placement is finalized. Verify explicit failure for an inconsistent internal plan before package rendering. Preserve source identities and metadata for provenance; they must not leak into emitted formulas.
3. **Exercise placement and removal.** Cover vertical zero/one/multiple repetitions, horizontal expansion, distinct owners, groups spanning static/repeated or separate ownership bands, removed master with retained followers, and retained master with removed followers. Confirm no synthesized holes, extra formula cells or replacement shared masters. Use the existing internal pipeline for representative nested ownership without activating public nested generation.
4. **Carry F-M312-1 through saved output.** Cover independent row/column reversal, mixed endpoint flags, endpoints meeting/crossing, equal-axis expansion and subsequent copying after reparse. Assert exact orientation, flags, qualifiers and untouched strings/functions. Reuse [EndpointOrder tests](../../../../MonoReport.Tests/Services/Feature012FormulaTests.EndpointOrder.cs) for unchanged parser/copy behavior; add only missing shared-output integration evidence.
5. **Exercise safety failures.** Cover a surviving normalized formula with a cropped operand, empty/disjoint/ambiguous image, incompatible mixed owners or displaced identity. Reuse shared metadata/overflow negatives and representative sheet/name cases. Require code, source cell, operand/remedy, unchanged input and no returned workbook. Preserve the F-001 regressions as separately tracked failures until the separately authorized correction passes them; do not weaken expected rejection.
6. **Inspect the generated package and round trip.** Reopen generated bytes with the SDK and validate schema plus independent semantic XML assertions: exact cell/formula counts and text; no shared formula type, `si` or `ref`; no stale formula caches or calculation-chain parts/relationships; automatic/full-recalculation settings; correct dimensions and PrintArea. Save/reopen a representative generated package and confirm those properties persist. Reparse or analyze scalar output to detect dangling shared followers. This is package-level round-trip evidence, not an application calculation result or a requirement to make rendered report data a new template.
7. **Run proportionate checks.** Start with new `SharedGeometry_` tests, then affected `SharedInventory_`, `SharedCopy_`, `EndpointOrder_`, formula diagnostics, owner/group/leaf/safety, cross-sheet/name and recalculation controls. Broaden only for actual changes or unresolved failures. Reuse [Recalculation_:17–41](../../../../MonoReport.Tests/Services/Feature012FormulaTests.cs#L17) for unchanged chain/cache mechanics, while adding shared-output assertions that can catch stale source metadata.
8. **Keep actual Excel verification pending.** [E1:363–368](../implementation-plan.md#L363) still requires a named Excel version, newly generated workbooks, no repair prompts, independent recalculated expectations, save/reopen and visual/print checks. Include shared-normalized formulas and the focused endpoint-copy observations described in [F-M312-1 §8](f-m312-1-architecture.md#L84). SDK validation, SDK save/reopen and LibreOffice evidence do not establish actual Excel compatibility. No browser automation, automated Excel or new application dependency is proposed.
