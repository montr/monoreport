## 2. Findings, ordered by severity

1. **F1 — High — Generated strings do not preserve SpreadsheetML escape sequences or carriage returns. Confirmed silent value changes.**

   **Locations:** [XlsxDocumentRenderer.cs:65](/Users/blackish/Projects/monoreport/MonoReport/Services/Xlsx/XlsxDocumentRenderer.cs:65) inserts prepared text directly into `t`; [XlsxDocumentRenderer.cs:40](/Users/blackish/Projects/monoreport/MonoReport/Services/Xlsx/XlsxDocumentRenderer.cs:40) saves with default newline handling. [XlsxTemplatePlanner.Binding.cs:37](/Users/blackish/Projects/monoreport/MonoReport/Services/Xlsx/XlsxTemplatePlanner.Binding.cs:37) verifies XML characters but performs no SpreadsheetML string encoding.

   **Reproduction and actual result:** Generate the ordinary static fixture described in section 4, with the complete scalar `{Name}`. JSON string `_x0041_` produces literal XML text `_x0041_`; `_x000D_` likewise remains unprotected. Under SpreadsheetML string interpretation these mean `A` and a carriage return, rather than the supplied literal spellings. Independently, JSON `a\rb` and `a\r\nb` both produce XML that parses as `a\nb`. All four merges succeed, and each output has zero Open XML validator errors. The carriage-return change was reproduced through both the actual CLI assembly and current Core.

   **Expected:** Preserve the supplied string value. Literal escape-looking sequences need their leading underscore protected, and carriage returns need preservation through serialization. Microsoft's [ST_Xstring implementation notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/bd0aa042-434a-4ca7-b25f-4e1fd25a954d) specify these escape rules. The interpretation of escape-looking output follows that documented rule; Excel itself was not launched during this review.

   **Requirement and correction:** Spec sections 3.2.4 and 7.1; M1.4/M1.6 scalar fidelity and inert inserted text. Apply appropriate SpreadsheetML string encoding without reparsing inserted expressions or altering preserved authored text. Add semantic string round-trip coverage: raw SDK `InnerText` equality alone cannot establish this behavior.

Neither result supplies the required coded field/location/data-path diagnostics.    **Expected:** Reject malformed scalar text through `TemplateException.Errors`, with source B3 and data path `$.Name`, before output publication. Normalize the decoding failure at the scalar boundary rather than broadly treating every `InvalidOperationException` as a malformed package.

   **Requirement and consequence:** M1.6/M1.7; spec section 8.5–8.7 and plan section 4.5.6–4.5.7. Core behavior was executed. The HTTP consequence is inferred directly from [Program.cs:49](/Users/blackish/Projects/monoreport/MonoReport.Api/Program.cs:49): this exception reaches the general 500 handler instead of the generation 422 contract. That particular HTTP request was not executed.
