## 3. Findings and remaining integration risk

1. **Confirmed defects: none.** There is no M3.5 finding requiring a reproduction or correction before acceptance.
2. **M3.4 integration risk — P2 impact if activated; nonblocking for M3.5. Merge candidates must become source-compatible and distinct.** [Merges.cs:85](../../../../../MonoReport/Services/Xlsx/XlsxGeometryPlanner.Merges.cs#L85) currently enumerates every row span in the region without source-block filtering or owner deduplication. Once M3.4 emits a parent's header and footer with the same owner, both spans can project the same authored merge and trigger the overlap rejection at line 97; unrelated child/parent spans can also become irrelevant candidates. The violated future invariant would be one projection per compatible source merge/data owner. The smallest correction, already assigned to M3.4, is to select candidates from compatible source row/block spans and deduplicate structurally equal owners before projection, with a real nested header/footer merge regression. This is not reachable through the current public nested guard and is not a new M3.5 defect. Do not implement that adaptation during this review.
