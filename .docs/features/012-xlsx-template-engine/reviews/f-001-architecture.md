# Feature 012 F-001 architecture analysis

1. **Recommendation and status — 2026-10-23.** Add source-domain coverage to the existing geometry projection, alongside output-image contiguity. Require every source address in an operand to have a compatible retained image; reject incomplete projections through `XlsxUnsafeFormula`. Keep current owner selection and merge semantics. This is a proposed correction to M3.1–M3.11 correctness, awaiting Owner approval for implementation. No production/test changes, M3.12 work, subagents or separate reviewer pass are included.

5. **Precise invariant.** Let R be the literal source rectangle on the resolved target sheet, and let scope mean the vertical/horizontal selection already chosen by formula relocation. For every source identity s in R, the selected projection of s must be nonempty. R must also be wholly inside source PrintArea. At a source address registered in ContentOwners, only jointly compatible retained content owners supply that projection; suppressed physical copies cannot compensate. At every other address, compatible source row and column spans supply its Cartesian images, including blank addresses without an authored cell element. Compatible displaced-source identities remain unsafe under the existing ambiguity guard. Successful acceptance additionally requires all selected images to form the existing faithful unique cell/contiguous rectangle; source coverage does not replace that proof.

6. **What scope may exclude.** Coverage is existential per source address, not per unselected repetition: exclude incompatible sibling instances of the same address when compatible instances still represent it. Continue collecting every compatible image, preserving selected multiplicity and output gaps. Do not compare source/output areas, require equal instance counts, or reject merely because an incompatible owner exists. For F-001, B3 has an exact child-owned image but B2 has no compatible parent-header image: reject. For a body-only B3:B3 operand, its current instance covers B3 despite excluded sibling spans: accept if its image is otherwise safe. Group descendant ranges may cover an address through several own descendants while excluding the next group. Header/Footer roles sharing one data owner remain compatible; different roles alone are not grounds for rejection. A source address with zero selected images fails even if another portion survives; a removed formula placement is still skipped entirely.

7. **Smallest common algorithm — Merges.cs:34–43.** Extend private `AxisImage` to return source coverage through an additional output Boolean while retaining its existing output-interval result. Materialize the intersecting, already compatibility-filtered spans once. Clip their source intervals to the requested interval, sort by source start, and merge overlaps/adjacency using a cursor: a gap before the next interval or an uncovered tail means incomplete. Separately retain the current output-coordinate sorting/coalescing. Repeated source intervals count once for coverage but all their output intervals still contribute. This costs O(n log n) time and O(n) temporary storage per axis call for n intersecting spans; it never visits individual source cells. No new service, public API, geometry map, ownership identity or general rectangle-union abstraction is needed.

8. **Ordinary path — Merges.cs:9–19.** Use that common axis routine with the unchanged `CompatibleVertical`/`Compatible` filters. Set `Complete` to PrintArea containment AND full row-source coverage AND full column-source coverage. Preserve the existing Empty/Disjoint/Cell/Rectangle classification of the surviving output. In particular, a smaller contiguous rectangle can retain its geometric kind while carrying `Complete=false`. Document this strengthened meaning on [XlsxRangeImage, XlsxWorkbookPlan.cs:7](../../../../MonoReport/Models/Xlsx/XlsxWorkbookPlan.cs#L7), without adding fields. Source coverage must check the entire interval, including interior gaps, rather than endpoints alone. Apply this in `ProjectInstances` itself so direct callers and the no-content-owner `ProjectReference` branch cannot diverge.

9. **Content-owner path — Owners.cs:88–132.** Retain the existing cutout partition of R into ordinary rectangles and distinct owner addresses. For each ordinary piece, AND both source-axis coverage results into `Complete`, and collect output images exactly as today. For each distinct affected source address, require at least one owner satisfying both compatibility predicates together; AND that result into `Complete`, and collect every compatible owner output. Initialize completeness from source PrintArea containment. Keep the existing row-band output-union proof. This partition proves coverage without a second rectangle coverage engine: each ordinary piece is covered by its two complete axes, and each removed point by compatible retained content. Do not check ordinary axis coverage across the unpartitioned R: a retained merge anchor can legitimately survive after its original physical column disappears. Keep [Owners.cs:82–87](../../../../MonoReport/Services/Xlsx/XlsxGeometryPlanner.Owners.cs#L82) ahead of this processing so displaced blank identities cannot alias retained content.

Make completeness explicit before the mixed-endpoint comparison: reject an incomplete primary image, and an incomplete alternate scoped image at lines 144–147, through `UnsafeImage`. That comparison currently checks only Kind/Rectangle and must not ignore a failed coverage proof. Preserve existing mixed-owner diagnostics for otherwise complete projections and retain all existing Empty/Disjoint/Ambiguous/scalar checks. No new image kind, warning, recovery, union synthesis or diagnostic framework is required. Existing [Finalize:54–83](../../../../MonoReport/Services/Xlsx/XlsxFormulaPlanner.cs#L54), operation-context aggregation and [handler:64–65](../../../../MonoReport/Services/Xlsx/XlsxTemplateHandler.cs#L64) prevent rendering/returning a failed workbook.

14. **Trade-offs and Owner decision.** Previously accepted truncated formulas will now fail; this is the intended safety correction, including when the omitted source cells are blank (`COUNTBLANK` can observe them). Interval coverage adds sorting/scanning proportional to existing spans and owner pieces, not worksheet area; the existing cutout/output-union costs remain. Source completeness is an additional safety condition, not proof of arbitrary Excel semantics or permission to redesign geometry. Automatically widening body scope to ancestors/global, allowing partial-source contraction, inferring zero for empty operands or manufacturing unions would require a separate Owner-approved contract decision and introduce wrong-group/data-integrity risks. Actionable rejection lets authors choose a valid compatible/global operand explicitly. No unresolved product decision blocks the recommended correction; approval of this proposal is required before implementation under the present task. Public nested activation, M3.12, RealHost and unrelated findings remain outside scope.
