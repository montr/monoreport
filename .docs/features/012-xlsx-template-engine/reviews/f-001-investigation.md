# Feature 012 F-001 investigation

1. **Outcome and boundary.** Independently reproduced on 2026-10-23 against the current staged implementation. A body formula authored as `SUM(B2:B3)` is emitted as `SUM(A2:A2)` without errors or warnings. The defect also occurs without a merge or any content-owner entry. No production code, approved contract, public guard, RealHost behavior, milestone, or existing staged file was changed. No separate architecture/reviewer pass or subagent was used.
2. **Authority.** The applicable contract is feature-spec.md §6.7–9 and §8.4–7, architecture-assessment.md §3 and §5.2, implementation-plan.md §5.3/M3.7 and its unsafe-image verification requirements, and docs/xlsx-template-compatibility.md item 9. These require faithful scoped ranges or actionable rejection. The historical schedule/preprocessing proposals do not override the approved plan. F-001 in m3.1-m3.11-implementation-review.md was treated as a hypothesis to test. M3.12 remains outside this investigation.
3. **Concrete reproduction.** The worksheet is named Report, with PrintArea B2:C3. A2 contains `$l(10).Items`, B2 contains `{Name}`, A3 contains `$l(40).Items`, B3 contains `{Price}`, and C3 contains `SUM(B2:B3)`. Input contains a level-10 parent named Parent and its level-40 child with Price 11. One variant adds the authored merge B2:C2; the other has no merge. In both generated packages, the retained header is A1, the body value 11 is A2, and the formula in B2 is `SUM(A2:A2)`. The header operand has vanished. Both generated packages pass OpenXmlValidator; package validity does not detect this semantic loss. No recalculated numeric result is claimed.
4. **Pipeline and exposure.** The reproduction uses the existing [RenderGroups helper](../../../../MonoReport.Tests/Services/Feature012FormulaTests.Groups.cs#L290): actual XLSX package reading, template planning, JSON binding, scheduling, geometry, merge/header ownership, instance binding, formula finalization, rendering, package disposal, and reopening. There are no fabricated projection maps. This helper intentionally exercises internal nested functionality without invoking public preflight. Separate probes confirmed that public Merge still returns XlsxUnsupportedFeature for the same templates through [the nested preflight guard](../../../../MonoReport/Services/Xlsx/XlsxGeometryPlanner.Reports.cs#L21). This investigation does not establish public reachability for another template shape.

7. **Root cause: scope selection.** [XlsxFormulaPlanner.cs:135](../../../../MonoReport/Services/Xlsx/XlsxFormulaPlanner.cs#L135) enables descendant selection only for group-header/footer ranges. C3 is a body formula, so the relative range retains its exact vertical owner. The scheduled parent path is [0], while the child path is [0,1]. [CompatibleVertical](../../../../MonoReport/Services/Xlsx/XlsxGeometryPlanner.Merges.cs#L22) rejects the parent's path for that child scope. Compatibility uses paths, region identity and optional descendant selection; it does not compare a Header/Body role enum. Different roles alone do not prove incompatibility.
8. **Root cause: merged/content-owner path.** [RetainMergeAnchor](../../../../MonoReport/Services/Xlsx/XlsxGeometryPlanner.Owners.cs#L25) registers B2 as a retained content owner. [ProjectReference](../../../../MonoReport/Services/Xlsx/XlsxGeometryPlanner.Owners.cs#L88) removes every affected source address from the remaining rectangles before compatibility filtering. B2 is removed, but its incompatible parent-owned image is not reinserted at line 114. B3 supplies the sole output image A2. The contiguity proof at line 121 verifies the surviving images only; dropping a boundary operand leaves a perfectly contiguous smaller image. Complete at line 117 checks only PrintArea containment, so this incomplete source projection is returned as Cell(A2), Complete=true. The review's cutout diagnosis is confirmed for this variant.
9. **Root cause: ordinary instance path.** Without the merge, ContentOwners is empty and [ProjectReference:89](../../../../MonoReport/Services/Xlsx/XlsxGeometryPlanner.Owners.cs#L89) delegates to [ProjectInstances](../../../../MonoReport/Services/Xlsx/XlsxGeometryPlanner.Merges.cs#L9). It filters row spans by owner before AxisImage, similarly drops the header, and checks only that the surviving row and column images are each contiguous. Its Complete flag also measures only PrintArea containment. A correction limited to incompatible ContentOwners would leave this variant broken.
10. **Root cause: final acceptance and emission.** [XlsxFormulaPlanner.cs:150](../../../../MonoReport/Services/Xlsx/XlsxFormulaPlanner.cs#L150) correctly rejects images reported as incomplete, empty, disjoint or ambiguous. It receives none of those indications here. A range operand may legally have a one-cell image, so it writes both endpoints as A2. [XlsxDocumentRenderer.cs:35](../../../../MonoReport/Services/Xlsx/XlsxDocumentRenderer.cs#L35) emits that finalized formula and removes its stale cache. Token parsing, arithmetic evaluation, cached values and crop offsets are not the origin of the missing operand.

13. **Correction approach A, recommended direction.** Add bounded source-domain completeness validation alongside the existing output-image contiguity proof, covering both content-owner projection and ordinary instance projection. Track which required source portions have a compatible projection, using intervals/rectangle pieces rather than a dense worksheet grid. An incompatible retained header must not disappear silently. Return an unsafe image through the existing XlsxUnsafeFormula path. This keeps the current architecture and diagnostic envelope, but the completeness invariant must distinguish legitimate scope-based exclusion of sibling instances from loss of a distinct source operand.
14. **Correction approach B, smaller but more fragile.** Add targeted rejection when a requested source portion exists only in incompatible owners/spans. This can address the demonstrated boundary cases with less bookkeeping, but a ContentOwners-only check is insufficient and duplicated checks can diverge. Rejecting whenever any incompatible owner exists is incorrect: other sibling instances normally contribute incompatible owners for the same source address while the selected instance supplies a valid image. Counting original/output rectangle area is also insufficient because expansion and retained header ownership legitimately change multiplicity.
15. **Correction approach C, higher behavioral risk.** Automatically include ancestor owners or relax body selection to descendant/global scope. This might preserve the displayed rectangle in this example, but would change approved body/leaf and absolute-anchor semantics, could include sibling groups or totals, and requires Product Owner scope approval. It is not recommended as a bug fix. An actionable authoring rejection is sufficient; no function-specific unions, formula replacement, new parser or generalized ownership framework is needed.
16. **Regression risks and review recommendation.** Preserve structural path equality; valid ancestor horizontal header references; shared Header/Footer item ownership; group descendant ranges and their empty-group behavior; intentional sibling-instance exclusion; global/static/cross-sheet/name projection; dollar/mixed flags; blank/unauthored source cells; merge-anchor/displaced-source identity; and crop completeness. Recommend a focused architect review of the source-completeness invariant and placement of its checks before implementation, because the independently reproduced no-content-owner path broadens the proposed remedy and geometry is shared with merges. A broad architecture redesign or full separate review workflow is not necessary. No architect review or fix was performed here.
