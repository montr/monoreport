## Verdict

**Ready with findings.**

M3.12 correctly implements the main source-level contract: it inventories authored shared groups, identifies the master by `ref`, parses the master once, resolves worksheet/name identities, and copies each retained follower in source coordinates with its dollar flags. It does not perform M3.13 relocation or shared-formula output, and existing formula/diagnostic behavior is otherwise unchanged.

One supported mixed-endpoint case is incomplete: when relative copying moves a range endpoint past an absolute endpoint, the copied range becomes descending and the whole plan is rejected. The failure is safe (no incorrect workbook is emitted), but it rejects a valid mixed-reference shared group. This should be resolved, or explicitly accepted as a documented limitation, before M3.13's shared-formula output is treated as complete.

## Findings

### F-M312-1 — Medium: A mixed range endpoint crossed by relative copying is rejected after reparse

**Evidence**

1. `MonoReport/Services/Xlsx/XlsxFormulaReferences.Shared.cs:35-37` copies each follower and immediately reparses the copied text: `Parse(Copy(master, ...), Location(member))`.
2. `MonoReport/Services/Xlsx/XlsxFormulaReferences.cs:31-42` (`Copy`) shifts each range endpoint independently, preserving its dollar flags. It does not reconcile endpoint order after the shift.
3. `MonoReport/Services/Xlsx/XlsxFormulaReferences.cs:101-102` rejects any range whose last endpoint is above/left of its first endpoint with `Use increasing rectangular A1 range endpoints.`
4. The review probe `MonoReport.Tests/Services/Feature012FormulaTests.ReviewM312.cs:33-51` creates a master `B3 = SUM(A3:$C$3)` in group `B3:F3` and expects the follower `F3` to normalize to `SUM(E3:$C$3)` or the equivalent canonical `SUM($C$3:E3)`.

**Reproduction**

```text
dotnet test MonoReport.Tests/MonoReport.Tests.csproj -c Release --no-restore --filter 'FullyQualifiedName~ReviewM312_'
```

Observed result:

```text
MonoReport.Models.TemplateException : Use increasing rectangular A1 range endpoints.
  at MonoReport.Services.Xlsx.XlsxFormulaReferences.ReadSharedCopies(...) ...Shared.cs:line 42
```

The follower copy is `SUM(E3:$C$3)` (relative `A3` moved four columns right to `E3`; absolute `$C$3` stayed put). Because `E` is to the right of `C`, the public `TemplateAnalyzer.Analyze` path returns an invalid result and `Merge` throws without producing a workbook.

**Why this is a supported case**

1. Specification §6.9 supports explicit A1 rectangles with relative, absolute and mixed flags: `.docs/features/012-xlsx-template-engine/feature-spec.md:161`.
2. Plan M3.12 requires relative-copy semantics “respecting dollar flags”: `.docs/features/012-xlsx-template-engine/implementation-plan.md:120,214`.
3. The authored master is a normal increasing rectangle and is accepted. Only the copied follower becomes descending. Excel accepts a range such as `SUM(E3:$C$3)` and treats it as the same rectangle (`C3:E3`); the copy is therefore valid input, not an unsafe or corrupt construct.

**Impact**

A valid shared group with a mixed range endpoint can fail analysis/merge. No wrong formula or partial workbook is emitted, so the failure is safe, but the “mixed references” contract is incomplete. The same code path affects both axes and both mixed endpoint orders; the probe demonstrates the rightward case.

**Recommended correction**

Choose one of these explicitly:

1. **Preferred:** in `Copy`, after moving both endpoints, detect descending order and canonicalize the copied range into increasing order while preserving the rectangle and the flags attached to each endpoint (for example `SUM($C$3:E3)`), or make `Read` accept descending ranges and normalize the internal rectangle used by later relocation. Add tests for relative-first/absolute-last and absolute-first/relative-last ranges, copying left, right, up and down, including the crossing case.
2. If the product decides that descending copies are out of scope, reject the master/group with a specific diagnostic explaining that mixed range endpoints cannot be copied past an absolute endpoint, document the limitation, and correct the M3.12 “mixed ranges” claim. This is less consistent with specification §6.9 and should be an Owner decision.

The review probe's second test intentionally fails until this is resolved; it is not evidence of a pre-existing regression or an F-001 change.

## Test coverage assessment

The committed M3.12 tests are otherwise strong:

1. `SharedCopy_Followers_before_master_use_source_offsets_and_preserve_each_dollar_flag` (`MonoReport.Tests/Services/Feature012FormulaTests.SharedCopy.cs:14-52`) asserts exact text for every follower, every `$` flag, ranges, ordinary overrides, holes, source XML immutability and input immutability.
2. `SharedCopy_Forward_two_axis_copy_reparses_growing_reference_spans_without_touching_literals` (`...SharedCopy.cs:54-79`) independently checks two-axis growing spans and exact reference offsets.
3. `SharedCopy_Master_operands_resolve_sheet_identity_and_names_without_copying_name_definitions` (`...SharedCopy.cs:81-110`) covers cross-sheet qualifiers, escaped apostrophes, local-name precedence and name definitions.
4. Repeated instances, unsafe master operands, follower overflow/underflow and Analyze/Merge parity are covered (`...SharedCopy.cs:112-158`).
5. Inventory/crop/metadata tests (`Feature012FormulaTests.SharedInventory.cs`) cover master lookup, worksheet-local indices, invalid/overlapping groups, wholly cropped groups and the M3.12/M3.13 guard.

Meaningful gaps:

1. **No mixed range endpoints in the committed suite.** Mixed flags are tested only on scalar operands (`$D4`, `D$4`); the range cases use two relative endpoints (`B3:C3`, `D4:E4`, `Z9:AA10`). This gap allowed F-M312-1. Add at least one passing increasing mixed range and one crossing case in each axis.
2. **No assertion of the normalized follower text when the master lies outside the PrintArea.** `SharedInventory_Crop_does_not_hide_the_master_or_an_invalid_follower` (`Feature012FormulaTests.SharedInventory.cs:154-173`) checks the retained member's `SharedFormulaIndex` and the relocation guard, but not the copied formula text. The behavior is likely correct; an assertion would protect the source-coordinate copy contract.
3. **The crossing case is only exercised through the internal planner.** A public `Analyze`/`Merge` parity test would make the user-visible failure and diagnostic location explicit. The existing `AssertSharedInventoryFailure` helper is suitable for this.

## Scope and milestone boundaries

1. M3.12 does not enable M3.13 behavior. `XlsxFormulaPlanner.RequireScalarFormulas` still rejects every retained shared member in both `ValidateStaticReferences` and `Finalize` with “requires shared-formula relocation before scalar output” (`MonoReport/Services/Xlsx/XlsxFormulaPlanner.cs:85-95`). `SharedCopy_Repeated_instances...` and the inventory tests assert this guard. No shared-formula `<f>` output, cache cleanup or owner relocation is implemented here.
2. Normalization happens in source coordinates before binding/relocation. The repeated-instance test asserts the source cell formula remains the normalized source formula and that finalization still fails at the pending-relocation guard.
3. The public nested-emission guard (“Nested emission and placement are pending in M3.”) is intact.
4. The two F-001 failures are unchanged; no F-001 code, tests or range semantics were touched.
5. The review added only the untracked test file; no production or documentation changes were made.

## Can M3.13 begin?

**Yes, conditionally.** M3.13 can begin on the implemented increasing-rectangle subset because normalization, identity resolution and the pending-relocation guard are in place. However, F-M312-1 affects the normalized formula model that M3.13 will relocate and emit; it should be fixed first, or explicitly accepted by the Owner as a documented limitation, before M3.13's shared-formula output is considered complete. Starting M3.13 without that decision would carry a known mixed-reference gap into the emission milestone.

## Conclusion

M3.12 is **ready with findings**. The core master-once/follower-copy design is sound, the committed tests are behavior-focused, and no M3.13 scope has leaked into the implementation. Resolve or explicitly accept F-M312-1 and close the mixed-range test gap before treating the shared-formula capability as complete.
