## 3. Existing-interface composition and compatibility

These legacy constructors retain their current externally supplied DOCX composition and support DOCX exactly as before. Do not manufacture XLSX dependencies or introduce optional service arguments/default implementations inside them.
2. Add straightforward internal overloads accepting each façade's existing dependencies plus `PackageFormatDetector` and `XlsxTemplateHandler`, and use them in `AddMonoReport()`. Keep the old public constructor callable for current manually composed Word usage. Validate supplied dependencies; do not construct service defaults internally, add optional dependency arguments, compatibility wrappers or a separate composition-mode abstraction. Existing manual Word composition need not manufacture new XLSX dependencies; documented dual-format composition is `AddMonoReport()`. Test these actual paths without hypothetical client equality/serialization machinery.
3. Change `AddMonoReport()` to `TryAdd` explicit factories calling those internal overloads, resolving all dependencies from the provider. Register internal XLSX services independently; preserve pre-registered façade/formatter/resolver/reader services. Test repeated registration, pre-registration overrides, null guards, transient façades, and legacy manually composed DOCX generation/analysis. A consumer that completely replaces an existing façade remains responsible for its composition.
4. Read from the caller's current position into a private seekable buffer and inspect the package root office-document relationship/main-part content type. Route all four currently accepted Word-family types—DOCX, DOTX, DOCM and DOTM—to the existing Word path. Route only ordinary XLSX to the new spreadsheet path; XLTX, XLSM, XLTM, XLSB and other Excel formats remain outside scope. Reject malformed/non-OOXML or missing/inconsistent main parts safely. Ignore filename/upload MIME as authority: a valid supported package with a misleading filename still selects its actual handler. Never use Word opening as the XLSX detection mechanism. Preserve existing Word package/main-part and opaque-part copy-through behavior; acceptance of macro-enabled Word main-part types is not a new macro-execution or exhaustive Office-fidelity promise.
5. Restore the private buffer position after probing. Open each selected document in its correct SDK type and close all SDK handles before publishing bytes. The input stream and JSON remain caller-owned and open, including nonseekable streams and streams with a prefix before the current position. Keep one buffered package per operation where possible; do not add a second format-specific input copy. Preserve `Inspect(WordprocessingDocument)` and the accepted Word render logic.
6. `Analyze` maps malformed/unsupported nonempty packages to an invalid analysis result as today. `Merge` throws `TemplateException` with bounded diagnostics and returns nothing. Preserve existing argument/null/unreadable-stream behavior. XLSX requires JSON object data per its specification; do not apply that new root restriction to DOCX scalar/mixed-array use.

No format registry, extra variants, custom record equality or format property in analyzer JSON is needed.

No second successful-diagnostic type or collection is introduced.

### 3.3. Settled HTTP and CLI successful-warning behavior

1. Keep both existing routes and their default behavior. Ordinary generation responses, including absent `Accept` and `Accept: */*`, remain raw document bytes. Preserve DOCX MIME and `document.docx`; XLSX uses `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` and `document.xlsx`. Preserve the count header only when warnings exist. Do not place warning arrays, encoded JSON, or diagnostic tokens in headers.
2. On the same `POST /api/documents/generate`, an explicit acceptable `Accept: multipart/mixed` selects HTTP 200 multipart for either format. One attachment contains the document with correct MIME/filename; `diagnostics.json` is an `application/json` attachment containing `format` (`docx` or `xlsx`), `fileName` and `warnings`, serialized directly from `MergeResult.Warnings`. Entries retain message, field/fieldCode, part, location, dataPath and optional code; an empty warning array is explicit. No additional Core severity field is needed. Bytes and warnings belong to one merge, without base64 or regeneration.
3. The generic writer takes document bytes, simple format metadata and the existing warning collection. Reuse it for Word and XLSX without DOCX warning-code generation, message parsing or extra storage/projection. CLI emits each successful warning to stderr for either format in returned order, with available code/source/data-path context and a warning label; stdout contains only binary document bytes. Warning success still exits 0. Preserve failure exit/error handling and output sentinel protection. These are settled decisions, including the intentional change to successful DOCX stderr.
4. Parse `Accept` with framework media-type handling: a wildcard alone never opts in; a multipart entry with quality zero never opts in; where a supported document media type and multipart are both explicit, select higher quality and prefer binary on a tie. Preserve the existing binary fallback for other Accept values rather than adding an unrelated 406 contract. Include `Vary: Accept` for the negotiated generation route. Document both successful representations in OpenAPI.
5. `GenerationMultipartResult` receives fully generated bytes and a fully serialized diagnostic part before response execution. Emit a fresh boundary and correct CRLF/closing delimiters; stream those prepared parts without creating another full workbook copy. Core/data/serialization errors must occur before headers/body start and retain Problem Details. Cancellation/client disconnect after transport starts cannot retract transmitted bytes; no-partial-output means no report publication on a generation/validation failure, not atomic network delivery.
6. Keep warnings in the body. Preserve existing Word messages, and produce safe bounded XLSX descriptions at creation. Do not silently truncate success warnings, conflate the 100-error policy with warnings, or introduce persistence/TTL/access-control infrastructure. Count XLSX warnings for resource measurements now; enforce an application-specific warning ceiling only after its separate approval. No new limit applies to DOCX.
7. Multipart transport and reuse for both formats are settled; do not reopen them as alternatives or add a product gate for routine JSON member names/media handling. Implement and test the same warning source across Core, CLI, HTTP and OpenAPI.

## 4. Workbook planning pipeline and invariants

### 4.1. Read-only source semantics

1. Inventory all worksheets and workbook references before mutation. Resolve each sheet's `_xlnm.Print_Area` using workbook/local sheet scope; require one finite rectangular area for every retained worksheet. Missing, invalid, external, whole-axis or disjoint areas fail with a remedy to set one finite PrintArea. Do not silently drop a worksheet or use named report regions. Retain only report content, while recognizing legitimate controls above/to the left before disposal.
2. Cell-adaptation methods in `XlsxPackageReader` classify formulas before inspecting strings. Resolve shared-string entries per source cell; tokenize inline/shared/rich text only within that cell. Preserve authored rich-run properties, whitespace and style IDs; replace scalar spans without retokenizing output. Formula braces/array syntax are never field expressions. For a complete unformatted scalar, prepare a native cell value; literals/escapes/interpolation/explicit formatters prepare text.
3. Discover the unambiguous left control column and top geometry-control rows from approved markers outside PrintArea. Normalize `$level`/`$l` and `$header`/`$h` keywords case-insensitively, preserving ordinal JSON collection names. Coalesce equivalent consecutive markers before building blocks. Diagnose conflicting control placements/associations rather than picking a column/row heuristically or inventing a coordinate option.
4. Build horizontal nodes from same-level consecutive marked columns on their respective top rows; each node has a source interval, numeric level, associated root collection, ordered children and own columns between children. Validate containment, level order/association and one outer horizontally expanding region per sheet. Multiple contained child blocks at one level use the same level collection/tuple index; repeated template positions do not consume extra records.
5. Build independent vertical regions from maximal consecutive runs of marked rows. Coalesce identical normalized row markers into multirow blocks. Parse a recursive sequence of parent header, deeper children and optional parent footer using numeric level order, not consecutive integers. Every source block must have one interpretation. Reject ambiguous interleavings with the remedy to insert an unmarked control row. Static/separator rows remain outside all repetitions, even between identical markers.
6. The data-independent `XlsxTemplatePlan` includes sheet/part identity, PrintArea, source cells and spans, region trees, header-row blocks, ownership, parsed formula tokens/shared groups, names and coordinate-bearing feature inventory, requirements, occurrences and ordered diagnostics. Both analysis and merge use it. Analysis does not pretend to validate data-dependent matrix cardinalities or resulting reference images.

### 4.2. Ordered data and scopes

1. A neutral `DataScope` holds root JSON plus ordered current/ancestor values and indexed paths; resolver overloads accept it. Existing `Resolve(TemplatePath, MergeContext)` and `DataPath` behavior delegates without changing DOCX semantics. Keep XLSX ordinary vertical scopes, horizontal header scopes and intersection selection separate; the other axis is never an implicit ancestor.
2. Binding methods in `XlsxTemplatePlanner` resolve template-named root collections and compute the Cartesian product of distinct horizontal levels with checked arithmetic, preserving collection order. Repeated sibling template blocks reuse their level's tuple index. Parent-only columns do not increase matrix arity. With product L greater than zero, require L records per logical `$path` group; with L zero require exactly one descriptor. No horizontal tree means ordinary vertical-only records and optional `$path`. Binding/cardinality belongs to each sheet/region's applicable tree, never a workbook-global product; independent worksheets may use different root collections/counts.
3. Traverse vertical records once in input order. Validate path contiguity/non-reappearance, integer/consistent `$level` and exact arity; preserve first-record indices and tuple indices for diagnostics. Build hierarchy with a numeric-level stack; paths are opaque keys and slashes never infer parentage. Do not sort. An otherwise complete positional matrix permutation is undetectable without IDs; document producer responsibility.
4. A `LogicalRow` stores group key, numeric level, source record interval, first-record index, ordered children and ancestor identity. A `HeaderTuple` stores collection element indices by level, without materializing copied JSON objects. Ordinary fields/parent-only columns use first records; leaf fields use tuple-selected records; header fields use their header element; `../` and `$.` follow the specification's separate scopes.
5. Missing template levels render zero repetitions. Unmatched input levels emit stable warnings and omit only their own rendering while retaining unambiguous renderable descendants; keep their logical ancestry where needed for parent fields. If safe descendant ownership cannot be determined, report an error. Do not add exhaustive hierarchy validation or new recovery policies. Missing/null collection handling follows applicable existing resolver semantics; wrong non-null collection types fail. Explicit empties use the approved zero-repeat/descriptor rules.

### 4.3. One immutable final geometry/ownership plan

1. Use value identities: `SourceCellId(sheetId,row,column)`, `VerticalInstancePath(regionId,logicalRowIds)`, `HorizontalInstancePath(nodeIds,itemIndices)` and `CellInstanceId(sourceId,verticalPath,horizontalPath)`. Model intervals/rectangles in physical Excel coordinates, including zero-width columns. Region/node identity distinguishes two independent tables using the same collection/level.
2. First compute horizontal emission recursively for the entire printed row band: each collection instance emits its authored own-column/child sequence. A node's physical width is its item count multiplied by its own-column count plus expanded child widths. Empty children emit zero columns; nonempty parents retain own columns and headings. Empty outer collections remove all descendants. Preserve original own-column order, widths and hidden flags.
3. Compute every vertical region's instance spans, headers/bodies/footers and static row placement from source coordinates together. Prefix displacements place later regions and static totals once. Global worksheet rows/columns cannot satisfy independent conflicting movement; reject cross-owner collisions/incompatible neighboring row heights rather than deleting or duplicating a neighboring report.
4. Compose expansion with removal of external top/left margins and all content beyond the projected PrintArea. The final `XlsxWorkbookPlan` contains source-to-instance interval maps, final extents/PrintArea, owner spans, row/column properties and collision/resource totals. Source identities remain available after final coordinates change. Do not plan by repeatedly inserting columns, rescanning mutated XML and then deleting margins.
5. `ProjectRange(sourceRange, referenceScope)` returns an explicit image classification: unique cell, one contiguous rectangle, disjoint, empty, or ambiguous. Use compact intervals/owner spans instead of a dense worksheet or enumerating every blank cell. Check arithmetic/Excel dimensions and any already approved application limits before per-cell expansion; record resource counts without activating unapproved ceilings. Rendering materializes only authored populated/styled content and necessary structural ranges.
6. Geometry is frozen once. Merge/formula/metadata planners consume that same geometry snapshot; a final immutable workbook plan attaches their prepared decisions plus resolved values. No component mutates geometry after reference validation. No worksheet rendering starts until all sheets' data, placements, references, merges and supported features are safe. Recoverable independent value errors may be accumulated while preparing values, with no returned package if any exist.
7. Merge methods in `XlsxGeometryPlanner` assign existing source merges to owners. Project a parent-owned merge across a fully contained expanded child for each parent instance; preserve source anchor and nonanchor styles. One surviving cell becomes an ordinary cell; no surviving owner removes the merge/content. A surviving zero-width anchor keeps value/width/hidden flags without invented widening/hiding. Reject partial-child/cross-owner/disjoint projections, output overlap or loss of meaningful nonanchor content. Never add an unrelated merge or infer a heading.
8. Physically remove external cells, control row/column elements and disposable artifacts; update sheet dimensions, row/cell references, column spans, final `_xlnm.Print_Area`, supported names and print/view coordinates. Remove orphaned relationships/parts only where ownership proves they belonged solely to removed artifacts. Rebuild/prune shared strings used by retained cells so cropped sentinel/control content is not left in a shared-string part. Retain unrelated package settings/content safely; cropping is not permission to leave external cell content merely hidden.

### 4.4. Formula references and recalculation

1. Adapt the bounded scanner demonstrated by `research-spikes/InternalReferences.cs` into injected `XlsxFormulaReferences`; retain authored nonreference text and edit only parsed spans. Distinguish quoted strings/escaped quotes, numbers/exponents, identifiers/names, function calls, sheet qualifications, A1 endpoints and absolute/mixed flags. Add lexical negative tests; regex substitution and copying supplied spike targets are not a production implementation.
2. Normalize shared scalar groups from their actual package master/follower metadata before binding. Apply relative-copy semantics from master to each authored follower, respecting dollar flags, then treat every normalized scalar formula independently. Reject missing/conflicting masters, invalid follower membership and unsafe special formula structures. Verify real XLSX packages, including a follower before its master in traversal and masters/followers crossing a repetition/crop boundary.
3. Bind each operand to source sheet/name/owner identity before final coordinate emission. For a copied formula, select the compatible target instance by shared vertical/horizontal ancestor paths and relative-copy intent; `$` suppresses copy displacement, not structural movement. Do not apply output deltas and then relocate the same reference again. Resolve a scalar only to a unique cell; a range only to a faithful contiguous rectangle. Absolute anchors into multiple unrelated copies fail instead of selecting the first copy.
4. Header/footer ranges bind within the same logical group and descendants; a leaf formula binds its tuple; a static top/bottom total or separator formula has global scope. An operand's source interval and ownership must justify the selected image. Reject disjoint images rather than filling gaps with another group's totals. Authors can write an appropriate explicit retained contiguous range/union; the transformer does not infer business intent or synthesize unions. Existing explicit union operands are transformed separately when each maps safely.
5. Resolve same-workbook sheet names to stable sheet identities before planning any sheet, including escaped names and formulas on otherwise static sheets referencing expanded/cropped sheets. Resolve simple defined names with sheet-local precedence over workbook names; support only uniquely bound explicit same-workbook cells/rectangles, with verified dollar/copy semantics. Preserve name operands and transform their definitions where faithful. Reject formula-valued, relative-context-dependent, recursive or unresolved names when safe binding cannot be proved.
6. Preserve arbitrary ordinary function names over supported operands, including `SUM`, `COUNT`, `SUBTOTAL` and future-prefixed functions. Do not translate SUBTOTAL to SUM or evaluate any function. Detect geometry-sensitive constructed references, including prefixed/case variants of `INDIRECT` and unsafe `OFFSET`. Reject affected structured/external/3-D/whole-axis, spill, implicit-intersection and array/data-table forms, unsupported operators/tokens and unsafe names with the source formula cell, failing reference and remedy. A parser accepting a token is not proof that relocation is safe.

### 4.5. Native values, fidelity and diagnostics

1. Prepare native numeric/Boolean/string values for a complete unformatted scalar. Cover ordinary fractions such as 0.1 without incorrectly requiring exact binary rational representation. Recommend strings or explicit text formatting for unsafe values. Reject affected ambiguous/repeated/discarded title, break or pane projections with a remedy to remove/re-author that setting. Preserve provably unaffected settings unchanged. General print/view reconstruction and extra metadata handlers are optional future improvements requiring demonstrated need, not mandatory infrastructure.
5. Inventory names, tables, drawings/charts, conditional formatting, validation, hyperlinks, comments and extension/coordinate metadata. For each concrete fixture classify as supported transformation, provably safe preservation, wholly external disposal, or actionable rejection. Include coordinate movement caused solely by crop or later-table displacement, dependent chart formulas, relationships and referenced cells. No relocation handler for affected tables/charts/drawings/CF/validation is presumed. 6. `XlsxOperationContext` owns ordered errors and the single `MergeDiagnostic` warning list; it need not inject a collector service. Order by sheet/source row/column, then logical/tuple input order. Warnings carry available part/cell, indexed data path and optional stable code; their channel supplies severity. Errors use existing coded diagnostics. Preserve Word codes/messages.
