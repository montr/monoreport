## 2. Findings

1. **S1-01 — Unknown shared-string table extensions are accepted and silently deleted. Status: Fixed (2026-10-26); independently verified (2026-10-26), blocker resolved. Original severity: Medium — implementation acceptance blocker.**

   **Affected work:** Stage 1 sections 4.2 and 4.4; shared-string package inventory and output conversion. References: [XlsxPackageReader.cs:26](../../../MonoReport/Services/Xlsx/XlsxPackageReader.cs#L26), [XlsxPackageReader.cs:134](../../../MonoReport/Services/Xlsx/XlsxPackageReader.cs#L134), [XlsxDocumentRenderer.cs:76](../../../MonoReport/Services/Xlsx/XlsxDocumentRenderer.cs#L76).

   **Evidence:** An independent public Analyze → Merge probe added an unknown extension payload under sst/extLst/ext in xl/sharedStrings.xml of a small workbook containing a shared rich-text field. The source passed the installed Open XML SDK validator with zero errors. Analysis returned Valid=true; generation succeeded and deleted the entire shared-string part, including the unknown payload. Reproduction inputs and output are /private/tmp/feature014-independent-review/unknown-shared-extension.template.xlsx and unknown-shared-extension.output.xlsx; the diagnostic runner is Program.cs in that directory.

   **Cause and impact:** The reader selects only si children from the shared-string table. ReadRichString checks structures inside referenced items, while the workbook feature inventory sees only the permitted sharedStrings relationship. Table-level extensions never reach compatibility validation. Rendering then unconditionally deletes the table after converting cells to inline strings. This violates Spec 2.1.4 and 2.4.2: unknown or meaningful extension content requires actionable rejection when safe preservation is unproven. The table-level inventory omission also exists in the prior path; Stage 1 leaves this required safety boundary incomplete. It is separate from the correctly bounded workbook save-path classifier.

   **Recommended correction:** Validate shared-string table root content and its relationships before conversion/removal. Reject unsupported content at the actual shared-string part, retaining available cell context where useful. Extend an existing package compatibility scenario with a table-level unknown extension and assert analysis/generation agreement, unchanged input and no returned report. A narrow reader check is sufficient; no general metadata framework or new preservation capability is requested.

   **Correction and verification:** XlsxPackageReader now validates the shared-string table root, ordinary count attributes, direct content and relationships before selecting items for conversion. Unsupported structures, attributes or relationships receive an actionable template.xlsx_unsupported_feature diagnostic at the actual shared-string part; existing referenced-item checks retain their worksheet/cell context. XlsxPackageCompatibilityTests.Unsupported_shared_string_table_content_is_rejected_before_conversion covers the reported schema-valid sst/extLst/ext payload plus unsupported table attributes and internal/external relationships. All four cases assert Analyze/Merge diagnostic agreement, unchanged source and no returned report. The focused package run passed 27 cases and the affected regression run passed 134 cases, with zero failures/skips, offline without Samples or examples manifests. Evidence: /private/tmp/feature014-evidence/review-fixes-package.trx and review-fixes-regressions.trx. No general compatibility framework or preservation capability was added.

## 3. Implementation assessment

1. **Optional PrintArea and identity geometry:** The nullable crop is separated from the full valid reference domain. Static and mixed repeated paths retain sparse cells/rows, coordinates, sheet IDs/order/visibility, dimensions and authored sizes without fabricating a print area or full-grid dimension. Missing-boundary controls use the existing prefix recognition before uncontrolled-sheet fallback. Existing invalid-area, crop, unsafe-reference and unsupported-setting checks remain relevant. No additional identity-geometry defect was established.
2. **Cross-sheet formulas and names:** Identity sheets participate in workbook-wide finalization. The mixed/all-uncontrolled scenario asserts references in both directions, supported names, implicit blanks on empty/formatting-only sheets, the Excel-limit coordinate and shared master/follower normalization on the identity reference sheet. Existing formula tests cover copy flags, ownership, cropped masters, invalid groups, unsafe images and recalculation cleanup. Analysis remains distinct from data-dependent generation success; an empty repeated operand can still correctly fail finalization.
3. **Views and generated content:** Valid ranges clip or reset without weakening formula safety; coordinate and explicit activeCellId inconsistencies reject before fallback. Ordinary attributes are retained and pane/synchronization/print-title boundaries remain enforced. Independent checks compared workbook and worksheet XML after removing only sheetViews, across 12 selection/count combinations, including zero, one and three records, whole-grid/multiple-range/outside selections and repeated viewport cells. Content, formulas and settings were identical to each baseline. Two additional no-PrintArea cases preserved sparse/empty content and print margins. These checks do not establish Excel UI fidelity.
4. **Rich text and annotations:** Decoded source spans and parsed token edits drive literal styling, opening-brace replacement styling, escaped braces and annotation relocation through the existing binding pipeline. Properties and annotations are cloned across shared/repeated occurrences; numbers/Booleans/empty values retain native storage and whole-cell style. Existing and new tests exercise shared/inline text, split fields, adjacent/empty substitutions, inert data, encoded text, Unicode, header/body/footer instances and shifted/removed phonetic hints. Additional public checks exercised cross-run native values and escaped textual insertion. No additional substitution defect was established. UTF-16 offset assertions remain synthetic evidence; Excel's non-BMP/PHONETIC behavior is unverified.
5. **Architecture, simplicity and rules:** Changes remain internal to existing XLSX services and data records, with no dependency, public transport/schema, evaluator, UI or Sample JSON expansion. The retention-domain representation and prepared rich payload are proportionate to approved requirements. Generated transport inputs and conditional optional copy items implement the approved sample-independence work. No separate implementation stage, unapproved user-visible behavior or unnecessary infrastructure was identified.
