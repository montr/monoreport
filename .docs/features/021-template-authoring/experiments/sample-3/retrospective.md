# Sample 3 execution retrospective

1. **Why faster: evidence and hypotheses.** [Recorded elapsed time](evidence/timings.json) was **362.3 seconds**, versus externally measured 502 and 608 seconds in the [earlier retrospectives](../sample-2/retrospective.md); different timing boundaries prevent a controlled comparison. Three levels increased semantic depth, but Sample 3 had one table, 29 rows, and 15 parts, versus Sample 2's 20 tables, 152 lines, and 23 parts. Three prototypes covered repeated rows. Rendering, PDF extraction, and OpenAPI download were omitted; evidence/hashes were consolidated and findings shortened. Individual savings cannot be isolated. Familiarity may have helped, but that is a hypothesis: earlier solutions/helpers were not inspected or reused. Earlier templates also worked initially, so first-attempt success does not explain the difference.

2. **Structural difficulties.** [Authoring](author.py) nested three marker-row pairs within one table, with the grand total outside. Tests emptied each level independently and retained empty children beside populated siblings. Heading rows have two physical cells spanning five logical columns; item rows have five cells. Horizontal `gridSpan` merges survived; vertical merges were absent and remain subject to the contract's rejection boundary. Formatting differed **between three row classes**, but matched within each: dark/white/bold project headings, pale group headings, and plain indented items. [Every original-data row was compared](evidence/verification.json), supporting those prototypes. The five-run title was edited through existing text nodes, retaining runs. This did not test differently styled characters within a replacement or opaque structures.

3. **Edits versus retries.** No DOCX edit failed or required repair. **Six successful renders produced five retained datasets**: the modified case was regenerated after choosing line-level cent rounding. This corrected test data, not the template. Missing `lxml`, sandbox-local HTTP access, and unreachable NuGet vulnerability metadata caused environment/setup failures. The successful SDK build took **21.46 seconds** ([log](evidence/validator-build.log)); invoking its DLL before the asynchronous build finished also failed. Earlier process-ordering advice was therefore not consistently followed.

4. **After 2m 22s.** That milestone meant generation, MIME extraction, and ZIP checking; semantic/formatting verification was incomplete. Another **220.0 seconds** elapsed: approximately **100.0 seconds** for changed/empty cases, verifier composition, rounding correction/regeneration, and data/preservation assertions at **4m 02s**; then **120.1 seconds** including SDK setup/results and reporting. These are wall intervals with overlapping work, not exclusive durations; the SDK timestamp records when completion was logged. Reuse could eliminate helper composition/setup, while mapping, expectations, rounding decisions, and checks remain necessary. No fraction or seconds-saving estimate is supported. The authoring script's roughly 15 ms runtime excludes composition and is not authoring duration.

5. **Prioritized additions to the future `monoreport` Skill.** Samples 1 and 2 already established transport/validator reuse and risk-based rendering. Sample 3 makes their needed behavior more specific:

   | Priority | Instruction or reusable capability | Sample 3 reason |
   |---|---|---|
   | 1 | Before generating changed numeric data, define line rounding, aggregation order, and expected totals using decimal arithmetic. | Would have avoided the modified-data correction and extra render; the original source did not establish a fractional-cent policy. |
   | 2 | Inspect logical table columns, merge spans, row formatting classes, and text/run boundaries together. Select a prototype per class and check equivalence before collapsing records. | Cell count and leading spaces worked as sample-specific inference cues, but are insufficient as a reusable classifier. More nesting did not require editing every record. |
   | 3 | Describe same-table loop scopes explicitly: matched sibling marker rows, local item context, header/total ownership, and expected rows when each collection is empty. Apply field replacement to verified text ranges while retaining run properties. | These were the actual additional authoring decisions; existing DOM facilities handled them without a new editor. |
   | 4 | Reuse a tested SDK invocation with known dependency/cache prerequisites and await its process handle before consuming outputs. Record append-only attempt events for render, extraction, semantic checks, and validation. | Avoid repeated restore/setup and premature execution. Current timestamp keys overwrite earlier attempts, obscuring the first modified generation and case preparation. Keep transport success distinct from semantic verification. |

6. **Direct OOXML boundary.** No new engine limitation emerged. Success depended on source-specific row/run indices, one text node per prototype cell, three formatting classes, and removal of editing-session identifiers from repeated prototypes. Preservation of per-record style exceptions, mixed-format fields, or identity-bearing objects inside repeats remains unproved. Word layout remains unverified. A trial targeting one such exception would add evidence; this result does not justify a DSL, dedicated editor, or architecture change.
