# Sample 4 — XLSX template authoring

1. **Outcome.** The initial template passed MonoReport Analyzer and generated all five cases without warnings. The source is an employee directory: one Employees worksheet, 10 merged department headings, and 100 employee/position pairs. No previous experiment solution or repository example template was consulted. The applicable XLSX contract and authoring guide were read. The Feature Developer skill was reviewed; implementation planning was inapplicable to this experiment.
2. **Deliverables and binding.** [Template](output/skill-sample-4.template.xlsx), [extracted original JSON](output/skill-sample-4.json), and [modified-data result](output/skill-sample-4.result.xlsx). The result uses [modified data](evidence/modified-data.json). Data is an ordered array: level 1 records contain Department; following level 2 records contain Name and Position until the next department. Empty departments have no following employee records. An empty Data array produces only the static header and blank margin row.
3. **Authoring approach.** Python standard-library ZIP/XML inspection and narrowly scoped XML text edits avoided a spreadsheet-library round trip. Original rows 1–4 supply the blank row, header, department, and employee styles. The three dynamic cells use {Department}, {Name}, and {Position}; helper cells A3/A4 use $level(1).Data and $level(2).Data. Moving report columns one position right and defining PrintArea B1:E4 preserves the original blank column A after generation crops back to A1. The department merge C3:E3 expands back into the original B:D geometry. No dedicated editor, DSL, production change, or Git mutation was made.
4. **Verification.** [Analyzer response](evidence/analyze.json) has zero errors and warnings. [Verification evidence](evidence/verification.json) covers every generated value, record order, cell coordinate and type, style index, blank styled cell, row attributes/heights, column widths/styles, merged ranges, dimensions, PrintArea, worksheet identity, views/selections, page margins, paper settings, ZIP CRCs, and XML parseability. Original-data worksheet and workbook XML are structurally identical to the source, including all 112 rows and 10 merges. Template controls and expressions are absent from generated values.

   | Case | Departments | Employees | Rows | Result |
   |---|---:|---:|---:|---|
   | Original | 10 | 100 | 112 | Exact source layout and data |
   | Modified | 3 | 14 | 19 | Department sizes 2, 0, 12; changed labels and positions |
   | Expanded | 11 | 101 | 114 | Additional department and employee |
   | Empty | 0 | 0 | 2 | Static header retained; no merges |
   | Empty children | 2 | 0 | 4 | Two merged headings; no employee rows |

5. **Package preservation.** Only workbook.xml and sheet1.xml change during authoring. The other seven package parts remain byte-identical through all generated cases: styles, theme, both relationship parts, content types, and both document-property parts. Therefore original fonts, borders, fills, alignments, and number-format definitions are retained. Sheet order/name, blank margins, print orientation, and worksheet structure are preserved. See [package evidence](evidence/package-preservation.json) and [artifact hashes](evidence/artifact-hashes.json).
6. **OOXML limitation.** [Open XML SDK 3.5.1 validation](evidence/openxml-validation.json), targeting Microsoft 365, reports exactly the same two source diagnostics for input, template, and all five results: pageSetup horizontalDpi and verticalDpi are 0, below the schema minimum of 1. No new diagnostics were introduced. The original settings were deliberately preserved; these workbooks cannot be described as schema-clean. This is consistent with the compatibility contract, which does not promise general Office validation. No contract discrepancy or engine failure was observed.
7. **Actual authoring failures.** Sandboxed localhost access initially failed; escalated local API requests succeeded. One unquoted curl form argument caused HTTP 400 request.empty_input; quoting it fixed generation without changing the template. Independent validator compilation initially failed because the NuGet vulnerability lookup was unavailable and warnings are treated as errors; using cached packages with NuGetAudit=false succeeded. Details are in [authoring failures](evidence/authoring-failures.json). No template revision was required after the initial attempt.

9. **Practical limits and reproduction.** Excel rendering, pagination, and application-open behavior were not tested; there was no unresolved structural layout concern requiring visual rendering. The report contains no formulas or numeric/date fields. Empty-child binding uses a flat level-ordered array rather than nested JSON arrays. Rerun author.py to rebuild template/data; submit template multipart field to /api/documents/analyze, then template and JSON data fields to /api/documents/render with Accept multipart/mixed. Saved response headers and MIME bodies allow verify.py to unpack and check original, modified, expanded, empty, and empty-children cases without further API calls. The isolated validation project uses cached DocumentFormat.OpenXml 3.5.1; NuGetAudit=false was a command-line build setting. No documentation outside this experiment needs updating.
