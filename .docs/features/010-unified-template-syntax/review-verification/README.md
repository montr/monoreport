3. The runner enforces source validity with `OpenXmlValidator(FileFormatVersions.Office2010)` and checks the approved expected behavior, deterministic analysis, ordered Analyze/Generate diagnostics, unchanged caller inputs, output validity, semantic comment references, external hyperlink fragments/relationships, and opaque field cache behavior. It reruns the historical comment-image case after adverse operations and performs eight concurrent merges with one shared engine. Exit code 1 means contract checks failed; it is the expected result on the reviewed implementation. The recorded run reported 12 failed assertions belonging to three defects, not 12 distinct defects. Exit code 0 would only clear this probe set, not establish Feature acceptance.
4. `zero-padded-comment-id.template.docx` contains three paragraphs: a loop opener, a complete comment attachment around `{.}`, and the loop closer. The text-only definition and every attachment use the legal source ID `00`. With A/B, Analyze is valid and Generate returns references `0,0` while the only definition remains `00`. Office 2010 output validation reports nine errors. One iteration reports three dangling-definition errors; missing/empty arrays succeed. Expected: distinct complete attachments resolving to cloned definitions, with conformant output.
5. `external-relationship-with-anchor.template.docx` has a hyperlink outside a loop, with an external relationship to `https://example.org/report.docx` and `w:anchor="Target"`. A separate local bookmark named `Target` is repeated. Expected: preserve the external link and generate normally. Actual: shared preflight rejects it as an unsupported internal anchor. `cloned-external-relationship-with-anchor.template.docx` moves that link inside the loop. Generation succeeds and validates, but changes its external fragment to `Target_1` and `Target_2`. Microsoft documents Word's external relationship plus anchor behavior in [MS-OI29500 section 2.1.521](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/df06e423-11a6-4a36-bfb3-82139e531781). Expected external fragments remain `Target` regardless of local bookmark cloning.
6. `field-begins-in-control.template.docx` puts a complex field's begin/instruction/separator inside an inline content control, with cached `{Name}` and its end outside, followed by ordinary `{Visible}`. Expected: only `{Visible}` is a dependency, cached `{Name}` remains literal, and visible text becomes `{Name}OK`. Actual: Analyze exposes both dependencies and Generate changes the field cache to `SHOULD_NOT_RENDER`. `field-ends-in-control.template.docx` puts the field end inside the control instead. Actual: Analyze discovers neither dependency and Generate leaves ordinary `{Visible}` unprocessed. Expected text is `cachedOK`. Both sources and outputs validate, and the controls themselves remain unchanged. These probes concern the existing opaque-field cache and expression-scanning contracts, not REF target resolution or field-code rewriting.
