## 3. Implementation-specific architecture record

1. Runtime diagnostic paths are derived from the same parsed `TemplatePath` and operation context used for data resolution. Diagnostics no longer use raw expression text as a substitute for a canonical JSON path.
2. A `{.}` occurrence is recorded at its canonical array-element path but does not add an artificial requirement node or element type. The containing `For` alone establishes the array requirement.
3. Requirement conflicts are tracked at recursive dependency nodes. Diagnostics are materialized after collection so earlier, later, and duplicate conflicting occurrences all retain their own part and location.
4. Missing structural warnings carry the original expression, canonical path, part, and location and are deduplicated by source occurrence across loop iterations.
5. Tracked-revision detection uses a small local traversal inside the DOCX planner rather than a separate public service or pre-parse architecture. This is necessary to detect table, row, cell, numbering, and section property-change elements that can exist outside paragraph text traversal; it also covers paragraph/run revisions and skips unsupported drawing/picture subtrees.
6. List rendering clones complete paragraphs and retains native `w:numPr`, `w:numId`, `w:ilvl`, indentation, styles, and the existing numbering part. It does not allocate numbering definitions or promise per-iteration restart.
7. Scalar replacement adds `xml:space="preserve"` when generated text begins or ends with whitespace so Word does not discard meaningful boundary whitespace.
8. The browser's existing simple-Word-field preview normalization remains isolated to preview compatibility. The engine treats all Word fields, including MERGEFIELD, as opaque unrelated OOXML.

### 16.2. Root causes and the common architectural gap

1. **F1:** `DocumentRenderer.CloneIdentities.Create` derives a bookmark map only from starts in the selected roots. An end whose start is outside those roots has no entry and is copied verbatim on every iteration. Mapping starts and ends independently would instead create unmatched ranges. `CompleteMetadataRanges` protects only marker containers; it does not establish ownership of ranges in bodies, branches, nested blocks, or surrounding content. Neither the planner nor preflight currently detects the unsupported intersection.
2. **F2:** `MergeContext.InitializePackageIds` already reserves drawing IDs from all reachable XML parts, including comments/glossary. Its allocator has sufficient scope. However, only `DocumentRenderer.Clone` remaps descendant `wp:docPr` IDs; `MergeContext.CloneComment` performs a second physical XML clone and changes only the comment ID. Reservation and allocation are different obligations: the comments clone bypasses allocation. Expanding the reservation set alone cannot repair this defect.
3. **F3:** names are allocated from current XML strings in each selected clone, and only anchors found in that same clone are redirected. A reference outside the clone is never visited. Nested selection clones from original planned source nodes, allocates another name, then deletes the intermediate enclosing clone. Thus an enclosing anchor can retain the temporary name of a target that never survives. This is a reference-ownership problem, not merely a suffix collision or allocator-lifetime problem. `If` also clones its selected branch, so removal and nested conditionals need the same analysis even without multiplicity.
4. **F4:** `RevisionDiagnostics` already walks the necessary story XML, including cell/property elements outside text paragraphs. The omission is its incomplete list of qualified revision names, not lack of reachability. Earlier tests exercise a few representative names and sometimes schema-incomplete fixtures; they do not demonstrate rejection of cell deletion or range markers. A new revision service/traversal would duplicate working infrastructure.
5. **Systemic conclusion:** F1–F3 share the absence of planned ownership and source-identity bindings across clone boundaries. Local remapping repairs wholly local pairs but assumes every reference and endpoint shares that local lifetime. F2 additionally demonstrates that allocation must run at every physical clone site. Keep the immutable plan, exact sibling operations, source-to-clone map, recursive renderer, and existing per-operation allocators. Add bounded DOCX identity metadata and ownership validation, rather than a general OOXML rewriting engine.

Use block identities, not JSON path strings: two loops over the same array are distinct scopes. Pair bookmarks by source ID within the independent root; never pair across a header/body or two separate footnotes/endnotes.
2. A supported bookmark has exactly one start and one later end, with matching ownership signatures. They may span multiple paragraphs, rows, cells, or complete tables when their ownership is the same. Allocate one new ID and name for the pair per surviving repeated instance. A malformed or incomplete pair affected by an operation fails planning; do not fabricate an endpoint. This is targeted operation validation, not a new general input-conformance validator.
3. Reject an endpoint inside a repeated/selected branch with its partner outside, in another branch, or in a different nested scope. Apply this to `For` and `If`, both crossing directions, nested blocks, and paragraph/row regions. Reject independently of data, including empty, null, missing, or one-element collections and currently unselected branches. This gives Analyze and Generate the same structural guarantee without data-dependent repair semantics.
4. A range whose endpoints remain outside and wholly enclose an operation is supported: both endpoints survive exactly once and continue enclosing the resulting zero/one/many content. A wholly local range disappears with its zero-iteration body or unselected branch. A complete pair within one marker container may disappear with that container, preserving the earlier marker-pair acceptance; a surviving hyperlink to that removed marker bookmark is unsupported.
5. Apply the ownership check to the already supported permission pair and comment attachment as well. For a ranged comment, its start/end/reference must travel together with one definition mapping; a reference-only comment is a point attachment and must not be rejected merely for lacking optional range endpoints. Clone it from its reference when repeated. Do not attempt tracked move-range repair; F4 rejects revisions first. These neighboring checks close the same lifetime gap without promising arbitrary OOXML range support.
6. Use existing `template.invalid_structure` diagnostics. Include the range kind, source ID/name, both endpoint coordinates and the conflicting block marker in bounded explanatory text. The diagnostic's primary location/source order identifies the first offending endpoint; its message identifies the other endpoint and owning control. Preserve `part`, `location`, and shared diagnostic conversion. Deterministic rejection is preferred because retaining a start with several ends, expanding a range, or assigning a crossing range to one iteration changes its meaning.

### 16.4. Proposed internal hyperlink contract — Product Owner approval required

1. Here “external reference” means a hyperlink outside the repeated region, as in F3. Actual external-document hyperlinks using relationships retain their relationship and target; they are not local bookmark references. For an internal `w:hyperlink/@w:anchor`, bind the source anchor to its source bookmark before cloning. Never resolve it by a generated suffix or by searching the final document for a convenient name. Hyperlink text remains opaque to template parsing.
2. A reference is supported when the target's ordered loop-scope sequence is a prefix of the reference's sequence and every conditional branch required for target survival also encloses the reference. Equivalently, whenever the reference survives there must be exactly one target in that reference's active scope. Conditions do not create iteration identities, but they do control survival. Use structural branch identity, not equality of Boolean expressions, to establish that guarantee.
3. **Same repeated scope:** bind the link to the bookmark in the same iteration, including forward references and targets in another sibling root. A reference outside a conditional cannot target a bookmark only inside that conditional. A reference and target inside the same branch may both disappear safely.
4. **Nested reference to enclosing target:** support an inner link to an unconditional bookmark in its active outer iteration or to an unaffected root target. All inner iterations use that same enclosing target. They must not use another outer iteration's bookmark. Ancestor identity bindings therefore remain available through nested rendering.
5. **Enclosing reference to nested target:** reject at preflight. The inner loop can produce zero, one, or many targets, and its cardinality is unavailable to Analyzer. In particular, the persisted nested F3 input is rejected even when supplied data happens to yield one child. Do not choose first/last, preserve the original name on the first child, or create a synthetic target around the repeated region.
6. **Reference outside a repeated target, or between sibling loops:** reject at preflight for the same reason. The persisted external F3 input is rejected. A root bookmark referenced from inside a loop remains supported. A cross-story reference to an unaffected unique bookmark can remain unchanged; one into a repeated/removable target must pass the same ownership test and normally fails.
7. **Zero iterations and conditional removal:** local links disappear with local targets; inner links to an enclosing target disappear safely when the inner scope is empty. A surviving reference to a potentially absent target is rejected statically, including an outside link into an `If`, opposite branches, or a marker bookmark. Do not silently remove the hyperlink or allow a dangling anchor based on runtime selection.
8. Preserve names of non-repeated bookmarks, including bookmarks moved through conditional selection only; their source originals are removed and there is at most one surviving instance. Allocate unique, length-constrained names for bookmarks with an enclosing `For`, and for bookmarks in newly cloned comment definitions whose originals remain, using the existing allocator. Reserve original names across the package, and reserve every allocation for the operation even if an intermediate clone is discarded. Validate uniqueness where an affected source anchor cannot otherwise be resolved unambiguously. Leave unrelated pre-existing unresolved anchors unchanged; this is not blanket hyperlink validation.
9. Use `template.invalid_structure` at the offending hyperlink location, with its anchor, target coordinates, and the loop/branch causing ambiguity or possible removal. Analyze must return `valid=false`; Generate must reject in shared preflight before rendering. No new public diagnostic fields or arbitrary fallback targets are needed. This static policy deliberately rejects some inputs that could be safe for particular data; approving that restriction is a product-contract decision.
10. The scoped binding guarantee covers explicit internal hyperlink anchors. Opaque Word fields, including `REF`, `PAGEREF`, and field-code hyperlinks, remain subject to the existing opaque-field contract: do not add a field-code parser or rewrite instructions/cached results. This proposal cannot claim to verify their target semantics. If full reference-field integrity is required, the Product Owner must approve that additional scope or a conservative restriction before implementation; it must not be silently described as covered by F3.

### 16.7. R1 recommendation and required decisions

1. The approved spec defines ordinary paragraph/table processing and explicit opacity for hyperlinks, fields, and specialized content, but never names content controls.
